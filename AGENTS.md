# AGENTS.md — правила работы агента в учебном проекте dealing-console-v2

## Назначение проекта

**dealing-console-v2** — учебный клон дилингового пульта РТУ. Цель: закрепить Vue 3, TypeScript, Pinia, Feature-Sliced Design и интеграции как в production **dealing-console-ui**, без полного паритета функционала.

- Backend: **RTU** и **APS**, как в рабочем стенде.
- Стек и подход: как в оригинале (Vite, Composition API, FSD, `@wui/common-library`, `@wui/jssip`).
- Electron, аппаратные контроллеры (Goose/Handset) — **позже**, после web-ядра; при планировании можно закладывать этап, но не смешивать с текущим шагом без явного запроса.
- Текст диплома и отдельная docs-репа **не входят** в задачи этого репозитория. Здесь только код, планы обучения и накопление знаний о **учебном** приложении.

**Главный приоритет агента:** научить и провести через реализацию; код в репозитории по умолчанию пишет **разработчик (ты)**.

---

## Целевой объём учебного приложения (MVP)

Не копируем весь dealing-console. Доводим до рабочего сценария звонковой части:

| Область         | Что входит (ориентир)                                                |
| --------------- | -------------------------------------------------------------------- |
| Звонки          | SIP/WebRTC, сессии, входящий/исходящий, базовое управление           |
| ПБВ             | Страница / зона панели быстрого вызова (упрощённо при необходимости) |
| Завешенные      | Панель завешенных линий, переключение, базовое управление            |
| Карточка вызова | Call card / call manager — ключевые состояния UI                     |
| Настройки       | Простые настройки (профиль/устройства/минимум preferences)           |

Конкретизация этапов — в `.ai/product/learning-scope.md` и в мастер-плане `LEARN-000-*`. Агент обновляет scope-файл, когда вы согласовали новый кусок MVP.

## Референс `.reference/`

В репозитории лежит **только для чтения** (не править без явной команды):

- `.reference/src/` — исходники dealing-console-ui;
- `.reference/.ai/` — wiki и материалы production-проекта.

**Правила для агента:**

1. При планировании и ревью **смотреть референс** — структура FSD, имена слайсов, паттерны Pinia, интеграции.
2. Если в референсе слабое или устаревшее решение — **сказать явно** и предложить вариант по Vue 3 / TS / FSD / типу realtime-приложения, не копировать слепо.
3. План можно строить **по референсу** (какие файлы, в каком порядке переносить/упрощать).
4. Копировать фрагменты из референса **можно**, когда ты в тупике или для рутины по твоей просьбе; при переносе — указать источник (путь в `.reference/`) и что упростили.
5. Знания **учебного** проекта копятся в **корневой** `.ai/`, не в `.reference/.ai/`.

## Чему агент учит (стек)

Агент ведёт обучение **на реальных шагах проекта**, а не абстрактными лекциями. В каждом плане и при ревью явно связывает «что пишем» с концепциями стека.

### Vue 3

- Composition API, `<script setup>`, `ref` / `reactive` / `computed` / `watch`.
- Lifecycle: `onMounted`, `onUnmounted`, cleanup listeners / timers / WS.
- Props, emits, `v-model`, слоты; когда выносить composable.
- Реактивность: почему теряется при деструктуризации, когда нужен `toRef` / `storeToRefs`.
- Шаблоны и производительность списков (`key`, не тащить тяжёлую логику в template).

### TypeScript

- `type` предпочтительнее `interface` (как в правилах проекта); избегать `any` и лишних `as`.
- Типизация props/emits, store state, DTO API, возвращаемых значений composables.
- Узкие union / const-объекты вместо enum; аккуратные generics там, где реально упрощают.
- Как читать ошибки `tsc` и чинить причину, а не маскировать.

### Pinia

- Store: state / getters / actions; composition-style stores (`defineStore` + setup).
- Когда store vs локальный `ref` vs composable.
- `storeToRefs` при деструктуризации реактивного state; actions можно деструктурировать напрямую.
- Не раздувать один глобальный store: границы по entities/features.
- Подписки и побочные эффекты — с явным cleanup.

### FSD

- Слои: `app` → `pages` → `widgets` → `features` → `entities` → `shared`.
- Public API через `index.ts`; импорты наружу только через алиасы и public API.
- Запрет «пробивать» слои и тащить `pages`/`widgets` в `entities`/`shared`.
- Куда класть store / UI / API-клиент в учебном слайсе.

### UI Kit и realtime (поверх стека)

- `@wui/common-library`: `wui-btn`, иконки через `prepend-icon`, токены `wrkspc-*` (не raw hex, если есть токен).
- `@wui/jssip`: связка SIP-сессий с Pinia и Vue lifecycle (подписки, cleanup).

**Как объяснять:** коротко «зачем» → что писать в файле → 2–5 строк паттерна / сигнатуры. Если ты спросил «как это работает» — разбор на примере текущего шага (и референса при необходимости), без воды.

В шаге плана можно помечать фокус: `Vue` / `TS` / `Pinia` / `FSD` (один или несколько).

**Тесты (Vitest):** на ранних этапах **не пишем**. Отдельная фаза в конце — обучение AAA и покрытию; до этого в планах помечать «тесты: позже».

## Workflow

```
Идея / LEARN-XXX → case.md → implementation_plan_N.md → одобрение («одобряю» / «начинай»)
→ один шаг (ты кодишь или агент по запросу) → проверка → ревью → ты коммитишь → следующий шаг
```

1. **Без одобрения плана** агент не начинает новый большой объём работ (кроме правок `AGENTS.md` / `.ai` по твоей просьбе).
2. **Один шаг плана = один логический коммит** (ты коммитишь сам).
3. После шага агент кратко: что проверить, что закоммитить, что дальше.
4. Если сделал `stash` — исправляем **текущий** шаг, не перескакиваем.

### Именование задач

- Формат: **`LEARN-NNN-kebab-topic`**, например `LEARN-001-routing`, `LEARN-012-pinned-calls-panel`.
- `LEARN-000-app-roadmap` — мастер-план разработки от ядра до фич (первая согласованная задача).

### Где что хранить

| Путь                                               | Содержание                                                                        |
| -------------------------------------------------- | --------------------------------------------------------------------------------- |
| `AGENTS.md`                                        | Постоянные правила (этот файл), **без** текста текущей фичи                       |

Язык: **русский** (планы, общение, комментарии в коде учебного проекта).

## Формат учебного `implementation_plan_N.md`

Планы **пошаговые, с подсказками к коду**. Блок «вопросы для самопроверки» **не используем**.

```markdown
# LEARN-NNN — [краткое название]

## Часть плана

[1–2 предложения]

## Шаг K: [название]

- **Зачем (коротко):** ...
- **Фокус обучения:** Vue / TS / Pinia / FSD (что закрепляем на шаге)
- **Референс:** `.reference/src/...` (если есть)
- **Файлы:** создать / изменить (полные пути от `src/`)
- **Подсказки реализации:**
  1. ...
  2. ... (что импортировать, что положить в store, какой composable)
  3. ... (фрагмент сигнатуры / псевдокод / ключевые строки — не обязательно весь файл)
  4. ... (если нужно — 1–2 предложения «почему так» по Vue/TS/Pinia)
- **Критерий готовности:** как увидеть результат в UI или в devtools
- **Проверка:** `npm run ...` или ручной сценарий
- **Кто пишет код:** ты / агент (если договорились)
- **Коммит после шага:** да
```

Для мастер-roadmap (`LEARN-000`): фазы (ядро → auth/config → SIP → entities → widgets → pages → settings), зависимости между фазами, без мелкой детализации всего сразу — детали в `LEARN-001`, `LEARN-002`, ...

## Ревью и проверка

После твоего шага агент:

1. Смотрит diff / указанные файлы.
2. Проверяет FSD, типы, idiomatic Vue 3 / Pinia (`storeToRefs`, cleanup listeners/timers), не только «работает ли».
3. При ошибках объясняет **почему** (реактивность, типы, границы store), а не только «замени на X».
4. Запускает по возможности: `npm run lint`, `npm run ts:check` (не гонять тяжёлый build без нужды).
5. Даёт конкретные правки, не переписывает проект целиком.

SIP/WebRTC и реальные звонки — **ручная** проверка на стенде; автотесты SIP не обещаем.

## Ограничения агента

1. Не добавлять зависимости без согласования.
2. Не менять public API (stores, IPC, routes) без необходимости и без отражения в плане.
3. Не править `.reference/`.
4. Не коммитить и не push без явной просьбы.
5. Не подменять обучение: если задача учебная — не выдавать готовую фичу целиком без твоей просьбы и без плана.
6. Минимальный diff; без «заодно отрефакторил соседнее».

## Связь с production

Этот репозиторий **не** production dealing-console-ui. Допустимы упрощения, другие имена внутренних модулей, меньший scope. При переносе паттернов из референса агент отмечает, что **намеренно упростили** для обучения.
