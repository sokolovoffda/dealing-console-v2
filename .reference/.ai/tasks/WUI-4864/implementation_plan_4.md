# Кейс: WUI-4864 — fast-dial API для сетки ПБВ

## Описание текущей части кейса

Третья часть WUI-4864 подключает сетку панели быстрого вызова к новому backend fast-dial. Новый backend хранит порядок и позиции карточек в сетке, а старый backend контактов/групп остается источником правды по группам и принадлежности контактов к группам.

Нужно завести слой `entities/fast-dial`, перенести туда API/DTO/нормализацию fast-dial и постепенно убрать временную frontend-модель `useQuickCallGrid`. Количество ячеек сетки фиксировано: 36. Поле `contacts[].order` из fast-dial трактуется как `cellIndex`, поэтому пустые ячейки между карточками допустимы и должны сохраняться.

## Контекст предыдущих частей

- `implementation_plan_1.md` — FSD-структура ПБВ и расширенные визуальные статусы карточек.
- `implementation_plan_2.md` — Swagger MCP, базовая grid-модель, edit mode, добавление/удаление контактов в ПБВ.
- `implementation_plan_3.md` — временное перемещение внутри группы через `useQuickCallGrid`, перенос между группами через старый backend состава групп, добавление контакта через старую модалку.

# План реализации: подключение fast-dial layout

## Шаг 1: Создать слой `entities/fast-dial`

- **Описание:** Завести FSD entity для fast-dial: типы DTO, API-методы, public API и базовую модель состояния/нормализации. API должен покрывать `GET /api/v1/me/fast-dial`, `POST /api/v1/me/fast-dial/groups`, `PUT /api/v1/me/fast-dial/groups/reorder`, `PUT /api/v1/me/fast-dial/groups/{id}`, `DELETE /api/v1/me/fast-dial/groups/{id}`. Нормализация должна явно отделить backend `order` от frontend `cellIndex`, ограничить позиции диапазоном `0..35` и не смешивать fast-dial layout с составом групп старого backend.
- **Файлы для изменений:** `src/entities/fast-dial/**`, `src/entities/fast-dial/index.ts`; при необходимости `.ai/tasks/WUI-4864/case.md`.
- **Ожидаемый результат:** В проекте есть публичный слой `entities/fast-dial`, который можно использовать из виджета ПБВ без private imports. Код ПБВ пока не меняется.
- **Проверка:** `npm run ts:check`.
- **Коммит после шага:** Да.
- **Нужно ли обновить project wiki:** Нет.

## Шаг 2: Подключить fast-dial layout к отрисовке сетки

- **Описание:** В ПБВ загрузить fast-dial panel и совместить его с контактами активной backend-группы. Старый backend остается источником списка групп и контактов, fast-dial только раскладывает карточки по ячейкам. Если для группы нет fast-dial записи, показать дефолтную раскладку по порядку контактов без создания fast-dial group на загрузке. Если контакт есть в старой группе, но нет в fast-dial, положить его в первую свободную ячейку. Если fast-dial содержит отсутствующий в группе `contactGuid`, не показывать его. На этом шаге убрать `useQuickCallGrid` из основного построения сетки.
- **Файлы для изменений:** `src/widgets/quick-call-panel/ui/QuickCallPanel.vue`, `src/widgets/quick-call-panel/model/use-workspace-group-contacts/use-workspace-group-contacts.ts`, `src/entities/fast-dial/**`; при необходимости новый внутренний composable виджета для сборки grid cells.
- **Ожидаемый результат:** Сетка ПБВ строится из контактов старого backend и fast-dial layout. При отсутствии fast-dial данных текущий UI не ломается и показывает дефолтный порядок.
- **Проверка:** `npm run ts:check`; ручная проверка загрузки ПБВ с группой, у которой есть fast-dial layout, и с группой без fast-dial layout.
- **Коммит после шага:** Да.
- **Нужно ли обновить project wiki:** Нет.

## Шаг 3: Сохранять перемещение внутри группы через fast-dial

- **Описание:** Перевести перемещение внутри активной группы с локального `useQuickCallGrid` на fast-dial API. При перемещении в пустую ячейку обновлять список `{ contactGuid, order }` для текущей fast-dial group. При клике по занятой ячейке менять карточки местами и сохранять обе позиции. Если fast-dial group еще не создана, создать ее первым изменением раскладки, затем сохранить контакты. Старый backend состава группы в этом сценарии не трогать.
- **Файлы для изменений:** `src/widgets/quick-call-panel/ui/QuickCallPanel.vue`, `src/widgets/quick-call-panel/model/**`, `src/entities/fast-dial/**`.
- **Ожидаемый результат:** Перемещение внутри группы переживает reload после успешного ответа fast-dial backend. При ошибке сохранения действие отменяется или остается в стабильном состоянии без optimistic рассинхронизации; ошибку достаточно логировать в консоль.
- **Проверка:** `npm run ts:check`; ручная проверка перемещения в пустую и занятую ячейку, reload страницы после успешного сохранения.
- **Коммит после шага:** Да.
- **Нужно ли обновить project wiki:** Нет.

## Шаг 4: Синхронизировать добавление и удаление контактов с fast-dial

- **Описание:** При добавлении контакта через существующую модалку сначала локально проверить, что контакта нет в активной группе. Затем добавить контакт в группу через старый backend и сохранить выбранную ячейку через fast-dial. Если fast-dial сохранение упало, не откатывать старый backend: при следующей загрузке контакт попадет в первую свободную ячейку. При удалении из группы удалить принадлежность контакта через старый backend и удалить позицию карточки из fast-dial layout.
- **Файлы для изменений:** `src/widgets/quick-call-panel/ui/QuickCallPanel.vue`, `src/widgets/quick-call-panel/model/use-quick-call-contact-transfer/use-quick-call-contact-transfer.ts`, `src/entities/fast-dial/**`; при необходимости `src/entities/group/model/use-group-store.ts`.
- **Ожидаемый результат:** Добавление и удаление контакта работают с двумя источниками данных: старый backend меняет состав группы, fast-dial хранит позицию карточки.
- **Проверка:** `npm run ts:check`; ручная проверка добавления в свободную ячейку, повторного добавления уже существующего контакта, удаления карточки.
- **Коммит после шага:** Да.
- **Нужно ли обновить project wiki:** Нет.

## Шаг 5: Синхронизировать перенос и дублирование между группами

- **Описание:** Обновить сценарий `Переместить в другую группу`: старый backend должен добавить контакт в целевую группу и удалить из исходной, fast-dial должен удалить позицию из исходной раскладки и записать позицию в целевой. Добавить сценарий `Дублировать в другую группу`: старый backend добавляет контакт только в целевую группу, fast-dial обновляет только целевую раскладку, исходная группа остается без изменений. Если операция падает, пока достаточно отменить действие и залогировать ошибку без сложного rollback UI.
- **Файлы для изменений:** `src/widgets/quick-call-panel/ui/QuickCallPanel.vue`, `src/widgets/quick-call-panel/model/use-quick-call-contact-transfer/use-quick-call-contact-transfer.ts`, `src/entities/fast-dial/**`.
- **Ожидаемый результат:** Перенос и дублирование между группами используют старый backend для членства в группах и fast-dial для позиции карточки в целевой/исходной сетке.
- **Проверка:** `npm run ts:check`; ручная проверка переноса между двумя группами, дублирования в другую группу, отмены pending action.

## Шаг 7: Создавать внешние контакты через backend API для ПБВ

- **Описание:** Заготовить API-метод создания внешнего контакта через `POST /api/v1/user/client/contact` в подходящем entity API-слое контактов. В `ChangeContactsModal` добавить опциональный `groupGuid?: string`: если он передан, кнопка создания внешнего контакта должна создавать contact на backend, отправляя `groupGuid`, `name` равный номеру, `number` равный номеру и пустой `email`, затем возвращать созданный backend contact с настоящим `guid`. Если `groupGuid` не передан, временно оставить старое IndexedDB-поведение, чтобы не сломать остальные места использования модалки. В ПБВ передавать `activeTab.groupGuid` в модалку, чтобы внешний контакт создавался сразу в активной группе и дальше сохранялся в fast-dial по backend `guid`.
- **Файлы для изменений:** `src/entities/contact/api/use-contact-api.ts`, `src/entities/contact/types.ts`, `src/shared/ui/modals/change-contacts-keyboard/ChangeContactsModal.vue`, `src/widgets/quick-call-panel/ui/QuickCallPanel.vue`; при необходимости `.ai/knowledge/wiki/domain/quick-call-panel.md`, `.ai/knowledge/wiki/backend-integration/api-routing.md`.
- **Ожидаемый результат:** В ПБВ внешний контакт не создается как локальный IndexedDB-only contact. При создании внешнего контакта из модалки ПБВ backend возвращает настоящий `guid`, этот contact добавляется в активную группу и может быть сохранен в fast-dial layout. Другие сценарии `ChangeContactsModal` без `groupGuid` продолжают работать по старому механизму до отдельного перевода на API.
- **Проверка:** `npm run ts:check`; ручная проверка: открыть ПБВ в edit mode, нажать `+`, ввести внешний номер, нажать создание внешнего контакта, убедиться что contact появился в активной группе и ячейке после успешного backend-ответа.
- **Коммит после шага:** Да.
- **Нужно ли обновить project wiki:** Да: зафиксировать backend-first external contacts для ПБВ и временный IndexedDB fallback только для старых сценариев модалки.

## Ограничения для этой части

- Создание новых `user` групп и кнопка `+` справа от табов описаны в кейсе, но не входят в этот план подключения раскладки.
- С 2026-06-16 backend готов для целевого сценария: ПБВ работает только с `user` группами; `predefined`/`predefinedShared` больше не используются для отображения ПБВ.
- Fast-dial не должен показывать контакты, которых нет в соответствующей группе старого backend.
- Fast-dial group не создается автоматически на загрузке только из-за отсутствия сохраненной раскладки.
- Пагинации в сетке ПБВ не будет; лимит сетки — 36 ячеек.
- `groupGuid` для создания внешнего контакта в API пока считается опциональным на frontend-уровне ради переиспользования модалки, хотя текущий backend может требовать его. Для ПБВ `groupGuid` всегда передается из активной группы.
- Глобальный отказ от IndexedDB для внешних контактов не входит в этот шаг: остальные зависимые сценарии будут переводиться на API отдельно.
