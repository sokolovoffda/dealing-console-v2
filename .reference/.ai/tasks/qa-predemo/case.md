# QA Predemo — проходка пользовательских сценариев v3.0

## Исходная задача

Подготовка к предпоказу для QA: пройти готовые части UI по пользовательским сценариям, по ходу фиксировать и закрывать проблемы (функционал, UI vs макеты, регрессии).

Готовые зоны (по текущему пониманию):

- header;
- footer;
- рабочие столы (snapshots);
- ПБВ;
- карточка вызова;
- история;
- справочник.

## Порядок проходки (согласован)

1. Header + Footer
2. Рабочие столы
3. ПБВ + карточка вызова (сложные сценарии)
4. История + справочник (довести и пройти)

По ходу проходки проблемы закрываем точечно, без побочного рефакторинга.

## Ограничения

- Не начинать фиксы до явного старта очередного блока проходки.
- Один блок проходки за раз; найденные баги фиксируем и чиним в рамках блока (или выносим в backlog блока, если блокируют дальше).
- SIP/WebRTC и физические устройства — ручная проверка.
- Не раздувать scope на незаявленные зоны (pinned panel WUI-5185, conferences, Turret APS UI и т.п.), кроме случаев, когда они ломают текущий сценарий.
