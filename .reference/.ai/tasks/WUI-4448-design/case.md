# WUI-4448-design — приведение snapshots рабочих столов к макетам Figma

## Исходная задача

Продолжение `WUI-4448` / `WUI-4448-p2`: привести UI рабочих столов (snapshots) к макетам Figma v3.0 и задуманному пользовательскому сценарию.

В `WUI-4448-p2` уже реализованы:
- snapshots API (`GET` / `POST` / `PUT` / `DELETE` на дополнительном backend);
- `useWorkspaceStore` как source of truth;
- базовое добавление/удаление виджетов;
- переключатель режима редактирования в header (`setSquareM`), но без полной интеграции в `WorkspacePage`.

Текущая `WorkspacePage.vue` всё ещё работает как прототип редактирования:
- `wui-select` для выбора layout;
- крестик удаления на виджете;
- inline context menu для добавления виджета;
- `isWorkspaceEditMode` из store не используется на странице.

Макеты Figma (файл `JTPlAtfAfY1mawkWPsejsY`, «Дилинговый пульт v3.0`):

1. Ненастроенный рабочий стол — иконка + надпись по центру (`node-id=142-33291`).
2. Выбор доступной раскладки после клика (`node-id=115-22699`) — 4 варианта сетки (монопольная раскладка пока вне scope).
3. Экран после выбора раскладки — колонки по выбранному layout (`node-id=115-22748`).
4. Контекстное меню пустой колонки (`node-id=142-34002`).
5. Контекстное меню существующего виджета: переместить, удалить, замена через список других виджетов (`node-id=115-23241`).
6. Меню для виджета в середине — swap влево/вправо (`node-id=144-32477`).

## Уточнения пользователя

- 2026-07-13: Кейс оформляется как `WUI-4448-design`.
- 2026-07-13: Количество рабочих столов — **5** (как в текущем коде `WORKSPACES_COUNT = 5`).
- 2026-07-13: Пятый вариант раскладки / монопольная страница на весь стол — **пока не делаем**, логика layout остаётся прежней (4 варианта).
- 2026-07-13: Правило Jira «рабочий стол с 1 виджетом не допускается» — **не актуально**, один виджет допустим.
- 2026-07-13: `wui-select` для layout **полностью заменить** визуальным picker по макету.
- 2026-07-13: Пока на столе **нет ни одного виджета**:
  - в view mode показывается центрированная надпись с иконкой (без кнопок `plusAddM` в ячейках);
  - клик по надписи переводит в режим редактирования, кнопка `setSquareM` в header подсвечивается;
  - в edit mode доступен выбор раскладки, затем добавление виджетов;
  - если выключить edit mode до добавления виджета — снова показывается центрированная надпись.
- 2026-07-13: После добавления **хотя бы одного виджета**:
  - в view mode отображаются виджеты со стандартными пользовательскими действиями;
  - вход в edit mode для настроенного стола — через `setSquareM` → меню → «Редактировать»; выход из edit — повторный клик `setSquareM`;
  - в edit mode показывается сетка: виджеты (клик → context menu) или `plusAddM` в пустых колонках.
- 2026-07-13: Контекстное меню доступно **только в режиме редактирования**.
- 2026-07-13: Смена layout после появления виджетов — **нельзя**; только после удаления всех виджетов через context menu появляется пункт «Сменить раскладку» и открывается picker.
- 2026-07-13: Крестик удаления на виджете **убрать**; удаление только через context menu.
- 2026-07-13: Действия меню существующего виджета — **по макету полностью**: переместить (влево/вправо), удалить, замена типа через список доступных виджетов, swap с соседними колонками.
- 2026-07-13: Для 3-колоночной раскладки перемещение — пункты **«влево» / «вправо»** (для крайних — один доступный пункт).
- 2026-07-13: Пустые ячейки в edit mode — **`my-btn`** с `plusAddM` и токенами вроде `border-card-deal-border-state-add`, `text-card-deal-add-def` (аналог `comp/card/disp/bg/state/add`).
- 2026-07-13: Цвета — через design tokens / common library, не хардкод.
- 2026-07-13: Автотесты — **отдельным финальным шагом** плана.
- Сначала делаем **визуал и логику рабочих столов**; shared `ContextMenu` — generic с первого шага меню (шаг 4).
- 2026-07-13: Контекстное меню — **локальный shared `ContextMenu`** (`slot` + `useContextMenuPosition`), не `wui-list`. Стили panel — Figma `115-23241`; generic API сразу в шаге 4 (шаг 7 обобщения убран).
- 2026-07-13: Позиционирование меню — **привязка к конкретной ячейке/колонке**, в которую кликнули (не глобальное одинаковое меню по всему приложению). Референс — `usePositionPopUp` / `usePositionPopUpByDirection` (пример от команды либы); допустимо упростить и убрать лишнее. Activator = DOM-элемент ячейки сетки; содержимое меню зависит от состояния ячейки (пустая / с виджетом).
- 2026-07-13: На время реализации зафиксировать **`@wui/common-library`: `2.0.0`** (стабильные типы); `2.1.0-alpha.1` не использовать до фикса деклараций в либе.
- 2026-07-13: Кнопка **`setSquareM` в header** для **настроенного** рабочего стола (есть snapshot на бэке / виджеты): клик в **view mode** → сначала **`ContextMenu`** (activator = кнопка), не мгновенный edit mode.
  - **Редактировать** — включается обычный сценарий edit mode (picker / сетка / меню ячеек).
  - **Удалить** — `DELETE` snapshot **выбранного** рабочего стола (id из адресной строки), `router.replace` на draft слот, view mode, пустое состояние «Нажмите, чтобы настроить».
- 2026-07-13: Для **пустого** рабочего стола (нет snapshot на бэке): клик по надписи или `setSquareM` — **сразу** edit mode, без промежуточного меню.
- 2026-07-13: Если edit mode **уже включён**, повторный клик `setSquareM` — **сразу выход** в view (как сейчас toggle), меню не показывается.

## Ограничения

- Не менять бизнес-логику внутренних stores виджетов: snapshots управляют только визуальной раскладкой.
- Не добавлять новые npm-зависимости без отдельного согласования.
- API snapshots и правила `WUI-4448-p2` сохраняются: create без frontend ids, `PUT`/`DELETE` по snapshot, удаление последнего widget → `DELETE` snapshot + draft с layout.
- Монопольные страницы и монопольная раскладка — вне scope этой части.
- Drag and drop не входит; перемещение — через context menu.
- FSD: публичный API через `index.ts`, импорты через алиасы.
- Не дробить понятную логику на лишние helper-функции.
- `@wui/common-library` — версия `2.0.0` до отдельного согласования на alpha либы.

## Открытые вопросы

- Какой `Direction` по умолчанию для меню ячейки рабочего стола (например `BOTTOM_LEFT` / `BOTTOM_RIGHT`) — уточнить по макету при реализации шага меню.
- Нужен ли `usePositionPopUp` (координаты клика внутри ячейки) в дополнение к `usePositionPopUpByDirection`, или достаточно direction + activator = ячейка.
- Тексты/иконки пунктов меню `setSquareM` («Редактировать», «Удалить») — уточнить по макету при реализации шага 5.
