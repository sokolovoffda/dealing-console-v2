# Кейс: WUI-4733 — карточка контакта панели быстрого вызова

## Описание текущей части кейса
Часть 2: базовая визуальная модель карточки контакта панели быстрого вызова.

Нужно закрыть финальный подкейс для MR: сделать базовую подсветку карточек контактов в панели быстрого вызова по макету для состояний online/offline и заложить архитектуру под будущие приоритеты групп/контактов.

Текущие вводные:
- группы сейчас являются только компоновкой контактов;
- в будущем для контакта или пользователя в группе может прийти priority, по которому будет выбираться цвет карточки;
- набор priority-цветов будет ограничен;
- сейчас priority с backend не приходит, нужна только архитектурная заготовка;
- сейчас реализуем только default-вариант цвета и два состояния: online/offline;
- online-карточка должна быть яркой, offline-карточка тусклой;
- offline не должен быть простой opacity всей карточки, потому что дизайнер может задавать отдельные цвета фона, иконок, основного текста и вторичного текста для каждого priority/status;
- для будущего нужно предусмотреть отдельные токены вида `priority -> presence -> colors`, чтобы потом добавить red/brown/olive и другие варианты без переписывания карточки;
- источник online/offline нужно брать как раньше по SIP/BLF через `useContactStatusState`;
- сейчас карточка должна показывать по макету: иконку пользователя, номер, внизу имя;
- иконки будущих статусов звонков (входящий/исходящий и т.д.) сейчас не реализуем, но архитектурно предусматриваем место/типы для будущего расширения.

## Контекст предыдущих частей
- `implementation_plan_1.md` — базовый стор табов панели быстрого вызова: табы переведены на backend-группы, добавлены `useContactTabs`, глобальная инициализация в layout, отображение табов, загрузка контактов активной группы в виджете и отказ от preferences в новой логике.

# План реализации: базовая карточка контакта панели быстрого вызова

## Шаг 1: Описать визуальную модель карточки
- **Описание:** Создать локальную модель визуальных токенов карточки панели быстрого вызова: `ContactCardPriority`, `ContactPresence`, `ContactCardTone`, `CONTACT_CARD_TONES`. Заложить структуру `priority -> presence -> colors`, но реализовать только `default.online` и `default.offline`. Цвета хранить как классы/токены для фона, иконки, номера, имени и будущих status icons, без применения общей `opacity` ко всей карточке.
- **Файлы для изменений:** новый файл в `src/widgets/workspace-widget/model/` или подпапке `src/widgets/workspace-widget/model/contact-card-tone/`; при необходимости `index.ts` в этой подпапке.
- **Ожидаемый результат:** В проекте есть отдельная переиспользуемая модель цветов карточки, которую можно расширить priority-значениями без переписывания `WorkspaceContactCard.vue`.

## Шаг 2: Подключить online/offline через SIP/BLF status
- **Описание:** В карточке или отдельном widget-level composable определить presence контакта через `useContactStatusState`: для контакта брать `internalNumber`, находить статус в `contactStatuses`, `registered === true` считать online, отсутствие статуса или `registered !== true` считать offline. Не добавлять эту логику в `useContactTabs`.
- **Файлы для изменений:** `src/widgets/workspace-widget/ui/WorkspaceContactCard.vue`, возможно новый composable в `src/widgets/workspace-widget/model/`.
- **Ожидаемый результат:** Карточка выбирает online/offline на основе текущего SIP/BLF состояния, используя существующий статусный стор.

## Шаг 3: Подписать контакты активной группы на SIP/BLF presence
- **Описание:** Добавить widget-level подписку для контактов активной backend-группы: после загрузки контактов группы брать их `internalNumber`, проверять регистрацию SIP через `useWebRTC().onRegisteredSIP` и вызывать `subscribeSIP(internalNumber, 5 * 60)` по аналогии со старой логикой pinned calls. Подписку держать вне `useContactTabs`, потому что стор табов хранит только группы и не отвечает за контакты/SIP. При смене активной группы подписывать новые контакты; повторные подписки не должны ломать логику, так как `subscribeSIP` уже защищён от дублей через `activeSubscribers`.
- **Файлы для изменений:** новый composable в `src/widgets/workspace-widget/model/`, `src/widgets/workspace-widget/ui/WorkspaceContactsWidget.vue`.
- **Ожидаемый результат:** Контакты панели быстрого вызова получают SIP/BLF notify даже если они не закреплены в старой панели, а `useContactStatusState` начинает обновлять `contactStatuses` для карточек активной группы.

## Шаг 4: Привести разметку карточки к макету
- **Описание:** Обновить `WorkspaceContactCard.vue` под макет: сверху слева иконка пользователя, рядом крупный номер; ниже имя контакта. Применить tone-классы из шага 1 к фону, иконке, номеру и имени. Сейчас не рисовать будущие иконки входящего/исходящего звонка, но оставить аккуратное место/структуру для их добавления.
- **Файлы для изменений:** `src/widgets/workspace-widget/ui/WorkspaceContactCard.vue`.
- **Ожидаемый результат:** Карточка визуально соответствует базовому макету: online яркая, offline тусклая, номер и имя читаемы, цвета задаются не через общую opacity.

## Шаг 5: Добавить тесты визуальной логики карточки
- **Описание:** Добавить focused unit/component-тесты для `WorkspaceContactCard.vue` или composable: проверка online/offline presence, выбор default tone, отображение номера и имени. Моки `useContactStatusState` должны отражать SIP/BLF источник статуса.
- **Файлы для изменений:** новый или существующий тест рядом с карточкой/моделью в `src/widgets/workspace-widget/`.
- **Ожидаемый результат:** Тесты подтверждают, что карточка выбирает разные классы для online/offline и отображает данные контакта без моковых `test`-значений.

После завершения реализации очистить блок `Кейс (основная задача)` в `AGENTS.md`, не затрагивая постоянные правила.
- **Файлы для изменений:** `AGENTS.md` только на финальной очистке, тестовые файлы при необходимости.
- **Ожидаемый результат:** Карточка панели быстрого вызова имеет базовую подсветку online/offline, архитектурную заготовку под priority-цвета и будущие status icons, проверки проходят.
