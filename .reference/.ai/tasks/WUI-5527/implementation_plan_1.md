# План реализации: UI first → API later

## Шаг 1: Дизайн shell виджета настроек

- **Описание:** Оформить monopoly-страницу настроек по Figma: хедер «Настройки / {раздел}» + gear, слева сайдбар (состав пунктов **не менять**), справа область контента. Redirect на Main по умолчанию. Logout + version пока оставить.
- **Добить вёрстку/токены под макет (в рамках этого же шага, до коммита):**
  - цвет фона **асайда**;
  - цвет фона **контентной области**;
  - цвет **иконки в хедере** (`gearM`);
  - **шрифт** пунктов в асайде (размер/вес как в макете);
  - **активный пункт** меню настроек (фон/скругление/состояние);
  - **скругления** общего блока aside+контент — на макете вроде **без** radius;
  - **бордер** общего блока (aside + контент) по макету.
- **Файлы для изменений:** `src/pages/main/ui/settings-page/SettingsPage.vue`; i18n при необходимости; токены/классы по проекту.
- **Ожидаемый результат:** shell как в макете (структура + визуальные токены выше); контент Main открыт, область не пустая.
- **Проверка:** ручной просмотр `/main/monopoly/settings` vs Figma shell; смена раздела обновляет title.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 2: Дизайн «Основные настройки» на статичных defaults

- **Описание:** Переверстать `MainSettings` по Figma + согласованные доп. блоки. Данные из **локальных default-констант** (store/UI), без нового REST. Persist можно временно оставить как есть (IM) или отключить запись — главное, UI читает стабильный default-снимок для вёрстки.  
  Состав UI:
  - обучение: select + «Сбросить прогресс» (кнопка **без callback**);
  - локализация;
  - групповые вызовы (автозапись);
  - при снятии трубки: 2 свича (карточка / автоответ);
  - уведомления: мелодия, select рингтона, **громкость**, таблица/upload как сейчас;
  - «Сбросить настройки» (UI; действие на API-шагах);
  - **без PTT**, **без диагностики**.
- **Файлы для изменений:** `MainSettings.vue`; при необходимости типы/defaults в `entities/main-settings` (только статичные defaults для UI).
- **Ожидаемый результат:** Main визуально готов; работает на defaults без зависимости от нового API.
- **Проверка:** UI-review по макету + чеклист блоков выше.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

- **Файлы для изменений:** `entities/main-settings/api/*`, types, `index.ts`.
- **Ожидаемый результат:** типизированный API-слой.
- **Проверка:** unit mapper / `ts:check`.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 5 (позже): Store → REST вместо IM / locale localStorage

- **Описание:** Load GET, debounce PATCH, optimistic + rollback + тост. Locale из API. Training select — persist когда поле появится. Reset → PATCH defaults. Убрать IM `mainSettings`.
- **Файлы для изменений:** store, preference hub, locale wiring, тесты.
- **Ожидаемый результат:** Main persist на бэке.
- **Проверка:** GET→UI→PATCH→reload; fail → rollback.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Да (`im-preferences.md` и т.п.)
