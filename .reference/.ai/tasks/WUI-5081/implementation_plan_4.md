## Описание текущей части кейса

Предыдущая часть (`implementation_plan_3.md`) закрыла функционал пустой карточки: исходящий вызов из dialpad, интеграцию ПБВ, физический ввод с трубки, history, per-handset mute/volume и разнос общего shell в `CallCardLayout`.

## Шаг 6: Переключение по очереди и виртуальный empty-slot

- **Описание:** Расширить навигацию стрелками в карточке так, чтобы она переключала не только реальные сессии текущей трубки, но и виртуальную пустую позицию за границами очереди. Если у трубки есть очередь из `N` сессий, пользователь может выйти стрелкой на одну позицию до первой сессии (`0 / N`) или на одну позицию после последней (`N + 1 / N`). Дальше этой виртуальной позиции листание ограничено. Виртуальный empty-slot не включается в общее количество сессий и отображает расширенное empty-состояние: слева пустая карточка трубки со стрелками и счетчиком, справа queue вместо history. В этом состоянии можно набрать новый номер и создать исходящий вызов; после появления новой outgoing-сессии карточка выбирает ее. Клик по item в queue выбирает реальную сессию и выходит из виртуального empty-slot. Новый входящий вызов перебивает виртуальный empty-slot и выбирается по текущим правилам входящих. При завершении последней сессии трубки остается обычное empty-состояние с дефолтной правой панелью `dialpad`.
- **Файлы для изменений:**
  - `src/features/call-card/ui/CallCardWindow.vue`
  - `src/features/call-card/ui/CallCardEmptyState.vue`
  - `src/features/call-card/ui/CallCardSessionState.vue`
  - `src/features/call-card/ui/CallCardQueuePanel.vue`
  - `src/features/call-card/ui/CallCardLayout.vue`
  - `src/features/call-card/model/use-call-card-store.ts`
  - `src/features/call-card/model/call-card-session-selectors.ts`
  - `src/features/call-card/model/types.ts`
- **Ожидаемый результат:** Стрелки и очередь остаются синхронизированными способами выбора отображаемой позиции. Реальные сессии выбираются без побочных действий `unhold`/`hold`/`answer`; выход за диапазон открывает только виртуальный empty-slot для нового вызова. При наличии очереди empty-slot показывает queue справа, при отсутствии очереди работает обычный empty state.
- **Проверка:** Ручная проверка нескольких сессий: стрелки меняют карточку и selected item в очереди, не делают unhold/hold/answer, ограничиваются на `0 / N` и `N + 1 / N`, клик по queue item возвращает реальную сессию, набор из виртуального empty-slot создает новый outgoing и выбирает его. Проверить, что новый incoming перебивает виртуальный empty-slot, а после завершения последней сессии справа снова `dialpad`. `npm run ts:check` - только после отдельного согласия пользователя.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 7: Синхронизация footer со статусами сессий

Если карточка открыта, выбранная трубка показывает выбранную реальную сессию карточки, а virtual empty-slot отображается как свободная трубка. Если карточка закрыта, обе трубки показывают наиболее важную сессию по footer-приоритету `incoming high` -> `incoming regular` -> `outgoing` -> `active` -> `hold` -> free. Невыбранная трубка всегда работает как индикатор по этому приоритету: фон остается default/inactive, статусным цветом красится только иконка, текст остается handset inactive text token.

## Шаг 8: Ограничение одной active-сессии на трубку

- **Описание:** Добавить доменное ограничение: на одной трубке одновременно может быть только одна `active/CONNECTED` сессия. Если на одной трубке несколько исходящих вызовов перешли в `CONNECTED`, выбранная/актуальная сессия остается active, остальные connected-сессии этой же трубки переводятся в hold. Сессии другой трубки не затрагиваются, поэтому одновременно может быть по одной active-сессии на левой и правой трубке.
- **Файлы для изменений:**
  - `src/features/call-card/model/use-call-card-store.ts`
  - `.ai/tasks/WUI-5081/case.md`
- **Ожидаемый результат:** Несколько принятых исходящих на одной трубке не остаются одновременно active: активной остается одна сессия, остальные уходят в hold. На разных трубках active-сессии не мешают друг другу.
- **Проверка:** Ручная проверка: запустить два исходящих с одной трубки и принять оба; после принятия второго первый должен уйти в hold. Повторить сценарий на двух трубках: по одной active-сессии на каждой трубке должны оставаться active. `npm run ts:check` - только после отдельного согласия пользователя.

## Актуализация от 2026-07-03

- Шаги 1-2 расширены цветовой моделью `tone` и моделью раскладки `controlLayout`.
- Согласованная цветовая логика:
  - `outgoing` всегда `waitcon`;
  - `active` всегда `callcon`;
  - `hold` - `waitcon`;
  - `incoming` обычный - `warncon`;
  - `incoming` важный - `negcon`, с белым текстом.
- Иконки состояния зависят от стороны трубки:
  - исходящий: `arrowNorthEastM` / `arrowNorthWestM`;
  - входящий: `arrowSouthWestM` / `arrowSouthWestInvM`;
  - active/hold: `phoneCallF` / `phoneCallInvF`.
- Согласованная нижняя панель:
  - empty: справа `history + dialpad`;
  - outgoing: слева `transfer to other handset`, справа `queue + dialpad`;
  - active/incoming/hold: слева `hold toggle + transfer to other handset`, справа `transfer toggle + queue + dialpad`;
  - transfer mode остается вне текущего шага и будет согласован отдельно.
- Текущий ближайший фокус после модели/layout: довести handlers действий сессии, затем очередь текущей трубки, стрелки переключения сессий и footer sync.

## Вне рамок этого плана

- Transfer: blind/consultation/merge и transfer через очередь.
- Конференции: в этом плане не реализуем и не меняем никакие сценарии, модель или UI, связанные с конференциями.
- Сценарий `answer to hold`: принять входящий сразу в hold, не прерывая текущий активный разговор.
- Финальная полировка UI по макетам сверх минимального соответствия.
- Полное удаление или переписывание старых `call-manager`/`call-queue`, если это потребует отдельного безопасного пула правок.
- Автотесты до стабилизации контракта состояний карточки.
