# Кейс: WUI-5081 - Карточка вызова 3.0

## Описание текущей части кейса

Первая часть WUI-5081 закрывает базовую карточку вызова без подключения новой device-модели из WUI-5084. На текущей ветке используется старый `devices-store`, поэтому работа строится вокруг существующих `MediaDevice`, `DeviceType.HANDSET`, `handsetDevices`, `queueDevices`, `useSessionStore`, `useDevicesSessionsStore` и `useWebRTC`.

Нужно заменить старую раздробленную логику `call-manager` на единую карточку трубки: footer-кнопки двух трубок, открытие/скрытие карточки, выбор сессии, запуск вызова из ПБВ, очередь внутри карточки, DTMF и основные действия с сессией. Подключение финальной device-модели и точная полировка визуала остаются для следующих частей.

# План реализации: базовая карточка вызова на старом devices-store

## Шаг 1: Модель состояния карточки вызова

- **Описание:** Создать новую компактную модель карточки вызова, не продолжая старую state machine старого `call-manager`. Модель должна хранить открытую/скрытую карточку, выбранную трубку, выбранную сессию, режим правой панели (`queue` / `dtmf` / `null`), набранные DTMF/номерные символы, общий muted/volume state карточки как предварительный контракт. Добавить selectors для двух handset-слотов по порядку из текущего `devices-store`, определения disabled-состояния трубки и поиска активной сессии на трубке через текущий `devices-sessions-store`.
- **Файлы для изменений:**
  - `src/features/call-card/model/use-call-card-state.ts`
  - `src/features/call-card/model/types.ts`
  - `src/features/call-card/index.ts`
  - `src/shared/composables/state/devices-sessions-store/use-devices-sessions-store.ts` - при необходимости добавить недостающий публичный selector без изменения существующих сценариев
- **Ожидаемый результат:** Есть FSD-слайс `features/call-card` с публичным API и базовой моделью карточки. Существующий UI пока не заменен.
- **Проверка:** `npm run ts:check`; точечный ESLint по новым TypeScript-файлам.

## Шаг 4: Интеграция клика по карточке ПБВ

- **Описание:** Изменить действие `QuickCallContactCard`: в обычном режиме клик больше не завершает существующую сессию. Если сессия с абонентом уже есть, открыть ее в карточке. Если сессии нет и контакт доступен для звонка, запустить вызов на первой доступной трубке через текущий `useWebRTC().switchToCall(target, device)` и открыть карточку. Если первая трубка недоступна, не выполнять звонок и не ломать текущий UI.
- **Файлы для изменений:**
  - `src/widgets/quick-call-panel/ui/QuickCallContactCard.vue`
  - `src/features/call-card/model/use-call-card-state.ts`

- **Ожидаемый результат:** ПБВ становится первым источником открытия новой карточки: новый вызов стартует на первой трубке, существующая сессия открывается без завершения.
- **Проверка:** `npm run ts:check`; ручная проверка клика по online/внешнему контакту, клика по контакту с существующей сессией, клика при недоступной трубке.

## Шаг 5: Основные действия с выбранной сессией

При переносе на другую трубку активная сессия целевой трубки должна уйти в hold, а перенесенная стать активной через bind к устройству.
