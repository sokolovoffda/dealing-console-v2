# Кейс: WUI-5081 - карточка вызова 3.0

## Описание текущей части кейса

UI базовой пустой карточки, dialpad и history уже подготовлены в рамках предыдущих шагов. Следующая часть должна закрыть функциональный контракт пустого состояния без дальнейшей полировки верстки: запуск исходящего вызова из карточки и ПБВ, физический ввод цифр с контроллера, открытие карточки по поднятию конкретной трубки, а также подключение mute/volume к реальным операциям.

После этого нужно переходить к карточкам состояний вызова (`outgoing`, `incoming`, `active`, `hold`), а очередь текущей трубки делать уже после состояний вызова.

## Контекст предыдущих частей

- `implementation_plan_2.md` - базовая архитектура карточки, footer/dropdown, empty state, история, dialpad, будущие состояния вызова, очередь и полное поглощение старого `call-manager`/`call-queue`.

# План реализации: функционал пустой карточки перед состояниями вызова

## Шаг 1: Запуск исходящего вызова из empty-card dialpad

- **Описание:** Подключить кнопку call в `CallCardDialpadPanel` к существующему механизму исходящего вызова. Карточка, открытая через footer, должна позволять набрать номер и запустить вызов с выбранной доступной трубки. Если выбранная трубка недоступна, использовать доступную по текущим правилам выбора. Hangup в empty state остается disabled.
- **Файлы для изменений:**
  - `src/features/call-card/model/use-call-card-store.ts`
  - `src/features/call-card/model/call-card-actions.ts`
  - `src/features/call-card/ui/CallCardDialpadPanel.vue`
  - `src/features/call-card/index.ts`
  - связанные session/WebRTC helpers только при необходимости
- **Ожидаемый результат:** При наличии номера и доступной трубки кнопка call создает исходящую сессию, открытая карточка переходит из empty state в состояние вызова. Без номера или без доступной трубки вызов не стартует.
- **Проверка:** Ручная проверка: открыть карточку через footer, набрать номер виртуальным dialpad, нажать call. `npm run ts:check` - только после отдельного согласия пользователя.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 2: Интеграция ПБВ с новой карточкой

- **Описание:** Подключить клик по карточке ПБВ к новой call-card модели. Клик должен сначала проверить существующую нашу сессию с этим абонентом: если сессия есть, открыть ее карточку; если сессии нет, сразу инициировать исходящий вызов и открыть карточку. Для нового вызова использовать выбранную доступную трубку, а если выбранная недоступна - доступную по текущим правилам.
- **Файлы для изменений:**
  - `src/widgets/quick-call-panel/**`
  - `src/features/call-card/model/use-call-card-store.ts`
  - `src/features/call-card/model/call-card-actions.ts`
  - `src/features/call-card/index.ts`
  - `src/entities/call-session/**` только при необходимости чтения существующей сессии
- **Ожидаемый результат:** ПБВ больше не открывает старую карточку обычного трубочного вызова. Повторный клик по абоненту с существующей сессией открывает эту сессию, а не создает дубль.
- **Проверка:** Ручная проверка клика по ПБВ: новый абонент запускает вызов; абонент с существующей сессией открывает существующую карточку. `npm run ts:check` - только после отдельного согласия пользователя.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 3: Физический ввод цифр и поднятие трубки

- **Описание:** Подключить события контроллера для трубок к empty-card сценарию. Поднятие конкретной трубки открывает карточку этой трубки. Физический ввод цифр с контроллера автоматически открывает карточку выбранной или поднятой трубки, переключает правую панель на dialpad и вставляет цифру в позицию курсора текущего dial buffer. Компьютерная клавиатура в этот сценарий не входит. Нужен только backspace; Delete не добавлять.
- **Файлы для изменений:**
  - `src/features/call-card/model/use-call-card-store.ts`
  - `src/features/call-card/model/call-card-actions.ts`
  - `src/features/call-card/ui/CallCardDialpadPanel.vue`
  - `src/shared/controller/useHandsetPickupHangupHandler.ts`
  - `src/shared/controller/event-handlers/handsetEventHandler.ts`
  - `src/features/call-card/index.ts`
- **Ожидаемый результат:** Аппаратный набор ведет себя как ввод в dialpad текущей трубки: карточка открывается, dialpad активен, ввод идет в правильную позицию. Поднятие левой/правой трубки открывает левую/правую карточку.
- **Проверка:** Ручная проверка контроллера: pickup left/right, ввод цифр, backspace. `npm run ts:check` - только после отдельного согласия пользователя.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 4: Подстановка истории и сохранение per-handset UI state

- **Описание:** Зафиксировать поведение history и панели: клик по элементу истории только подставляет имя/номер и открывает dialpad, не звонит автоматически. Dial buffer и выбранная правая панель остаются раздельными для левой и правой трубки. Повторный клик по уже открытой правой панели не закрывает ее, потому правая область всегда заполнена dialpad/history/queue.
- **Файлы для изменений:**
  - `src/features/call-card/ui/CallCardHistoryPanel.vue`
  - `src/features/call-card/ui/CallCardEmptyState.vue`
  - `src/features/call-card/model/use-call-card-store.ts`
  - `src/features/call-card/model/call-card-history.ts`
- **Ожидаемый результат:** История работает как подготовка номера к вызову. При переключении трубок сохраняются отдельные dial buffer и panel mode.
- **Проверка:** Ручная проверка: открыть history, выбрать запись, убедиться что открылся dialpad с именем/номером; переключить трубки и проверить независимое состояние. `npm run ts:check` - только после отдельного согласия пользователя.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 5: Mute и volume как реальные per-handset операции

- **Описание:** Подключить mute и volume карточки к реальным операциям audio/device/session. Состояние должно быть раздельным для левой и правой трубки и синхронизироваться между всеми состояниями карточки. UI-кнопка mute и физическая кнопка mute меняют состояние этой трубки. Volume применяется к текущим и следующим сессиям выбранной трубки, насколько это поддерживается текущим audio layer.
- **Файлы для изменений:**
  - `src/features/call-card/ui/CallCardAudioControls.vue`
  - `src/features/call-card/model/use-call-card-store.ts`
  - `src/features/call-card/model/call-card-actions.ts`
  - `src/shared/controller/event-handlers/handsetEventHandler.ts`
  - `src/shared/composables/state/devices-sessions-store/use-devices-sessions-store.ts` только при необходимости helper для handset mute state
  - audio/WebRTC helpers только при необходимости существующего API
- **Ожидаемый результат:** Mute/volume больше не являются только локальной UI-заглушкой. Переключение между состояниями карточки не сбрасывает mute/volume выбранной трубки, а состояние другой трубки остается независимым.
- **Проверка:** Ручная проверка UI и физической кнопки mute, изменение volume на левой/правой трубке. `npm run ts:check` - только после отдельного согласия пользователя.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 6: Подготовка перехода к карточкам состояний вызова

- **Ожидаемый результат:** Empty-card функционально завершена, дальнейшая работа не смешивает базовый набор номера с UI/логикой состояний вызова и очереди.
