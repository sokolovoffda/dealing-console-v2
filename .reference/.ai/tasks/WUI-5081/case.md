# WUI-5081 - Карточка вызова 3.0

## Исходная задача

В версии 3.0 пульта управление обычными вызовами должно перейти в новую карточку вызова. Это единая модернизированная карточка, которая объединяет функциональность старого блока очереди вызовов и разных карточек старого `call-manager`.

Карточка открывается над footer по клику на кнопки трубок или по действию с карточкой панели быстрого вызова. В footer должны быть две кнопки трубок: левая и правая. Карточка работает только с телефонными трубками, не с Goose/завешенными линиями.

В целевом UI карточка умеет:

- отображать пустое состояние, если на выбранной трубке нет вызова;
- отображать выбранный вызов: имя абонента, номер, таймер разговора;
- выполнять вызов с карточки ПБВ;
- открывать существующую сессию в карточке, если сессия с абонентом уже есть;
- отвечать на входящий вызов из очереди на выбранной трубке;
- завершать вызов;
- удерживать вызов;
- переносить вызов между двумя трубками;
- открывать DTMF-панель и отправлять DTMF во время вызова;
- открывать очередь вызовов внутри карточки;
- регулировать громкость карточки вызова;
- включать/выключать микрофон карточки вызова через UI и физическую кнопку трубки.

- 2026-06-30: При клике по ПБВ сначала нужно проверить существующую нашу сессию с этим абонентом. Если сессия есть, открывается карточка этой сессии на конкретной трубке. Если сессии нет, сразу создается исходящий вызов и открывается карточка.
- 2026-06-30: Если на выбранной трубке уже есть активный вызов и запускается новый исходящий вызов, предыдущий активный вызов переводится на hold, новый вызов становится текущим.
- 2026-06-30: Очередь вызовов внутри карточки относится к текущей трубке, а не является общей очередью. В очередь карточки не попадают завешенные вызовы.
- 2026-06-30: Если карточка скрывается крестиком, внутреннее состояние желательно не сбрасывать. Введенный номер, выбранная вкладка/режим и текущий слепок карточки должны сохраняться, если это не усложняет реализацию.
- 2026-06-30: Трансфер при скрытии карточки можно сбрасывать. Если сохранение слепка трансфера не усложнит реализацию, допустимо сохранить и его, но базовое правило - не усложнять ради этого первую часть.
- 2026-06-30: Переключение трубки при открытой карточке оставляет карточку открытой, но показывает состояние другой трубки. Для будущей init-карточки от внешней карточки контакта переключение трубки сбрасывает init-контекст.
- 2026-06-30: История вызовов в пустой карточке отображает последние вызовы, клик по истории только подставляет номер. Сам звонок выполняется отдельной кнопкой вызова с выбранной/доступной трубки.
- 2026-06-30: Физический набор цифр на трубке должен работать как ввод номера, если нет активного вызова, и как DTMF, если активный вызов есть.
- 2026-06-30: Физическая кнопка ответа при наличии входящего отвечает выбранный входящий вызов; если конкретный не выбран, выбирается high priority, иначе первый входящий в очереди трубки.
- 2026-06-30: Постановка трубки на станцию не должна завершать все сессии. Базовое правило - перевести активный вызов этой трубки на hold; остальные вызовы на трубке уже находятся на hold.
- 2026-06-30: `mute` и громкость разделены по трубкам. Состояние не должно сбрасываться при переключении между вызовами внутри одной трубки.
- 2026-06-30: Перевод вызова активируется кнопкой `phoneTransferM` и работает только при активном вызове.
- 2026-06-30: В режиме transfer по умолчанию открывается dialpad. Очередь текущей трубки может использоваться как выбор цели перевода: клик по вызову из очереди открывает dialpad с подставленным номером.
- 2026-06-30: В dialpad режима transfer справа отображаются две кнопки: слепой перевод и перевод с сопровождением. Они активны только после ввода или подстановки номера.
- 2026-06-30: Слепой перевод выполняется только после явного клика по кнопке слепого перевода. На успехе исходная сессия уходит из нашей карточки; на ошибке пока логировать в консоль.
- 2026-06-30: Перевод с сопровождением создает новую консультационную сессию. Source-вызов переводится на hold в момент запуска консультации, не при включении режима transfer.
- 2026-06-30: В консультационной сессии dialpad работает как DTMF. Справа отображаются кнопки сброса консультации и merge. Merge доступен только после `connected` консультационной сессии.
- 2026-06-30: Сброс консультации завершает только консультационную сессию и возвращает пользователя к source-вызову на hold. При успешном merge пользователь выходит из обеих сессий, дальше карточка показывает следующий вызов трубки или пустое состояние.
- 2026-06-30: Переключение footer-трубки во время transfer отменяет transfer-режим и открывает карточку другой трубки. Source, если он уже был поставлен на hold из-за консультации, остается на hold.
- 2026-06-30: Перевод через очередь не выполняется стрелками переключения сессий. Для выбора цели перевода нужен явный клик по элементу очереди; стрелки только листают текущие сессии.
- 2026-06-30: Карточку планируется размещать через top dropdown, если библиотечный dropdown можно доработать без доменной логики. В библиотеку не должна попадать логика трубок или вызовов; допустимы только generic-возможности вроде controlled open, placement, outside/escape close, teleport/z-index.
- 2026-06-30: Backend не знает, на какую трубку должен попасть входящий вызов. На первом этапе frontend сам решает routing входящего: новые входящие вызовы кладутся в очередь выбранной доступной трубки. Точная будущая логика распределения входящих будет уточняться отдельно.
- 2026-06-30: Карточка скрывается только по крестику. Click outside и `Esc` на первом этапе не скрывают карточку; если потребуется, это будет добавлено позже.
- 2026-06-30: Клик по уже выбранной трубке footer при открытой карточке ничего не делает.
- 2026-06-30: При поднятии физической трубки карточка должна открыться. Если пользователь начинает набор на свободной трубке, карточка открывается в init/empty-состоянии с вводом номера.
- 2026-06-30: Если новый исходящий вызов перевел предыдущий active-вызов на hold, а новый вызов завершился, сорвался или получил ошибку, предыдущий вызов остается на hold и не возвращается active автоматически.
- 2026-06-30: После сброса текущего active-вызова карточка показывает следующий вызов трубки, но не делает его unhold автоматически.
- 2026-06-30: Клик по истории вызовов подставляет не только номер, но и имя, если оно есть.
- 2026-06-30: Очередь трубки отображается одной лентой без визуальной группировки по статусам.
- 2026-06-30: В transfer через очередь выбранный элемент используется как target. Если это уже наша локальная сессия, она становится unhold и в карточке помечается как консультация.
- 2026-06-30: Правки `@wui/common-library` для dropdown пользователь будет делать отдельно. В WUI-5081 нужно опираться на доступный библиотечный dropdown/его будущую версию, без самостоятельного переноса generic-правок библиотеки в эту ветку.
- 2026-06-30: Реализацию нужно делить минимум на две части: базовая карточка с footer/device/queue и отдельная часть для transfer.
- 2026-06-30: Новая карточка вызова полностью поглощает старые `call-manager` и `call-queue`. Совместимый legacy-layer для обычных трубочных вызовов не нужен: в приложении должна остаться одна реализация управления такими вызовами - новая карточка как совокупность карточки и очереди.

## Ограничения

- Не начинать реализацию до явного одобрения плана.
- Раннее ограничение от 2026-06-25 про старый device store актуально только до мержа WUI-5084 в `develop`. После мержа WUI-5084 план WUI-5081 должен опираться на новую модель device store.
- Не добавлять новые зависимости.
- Соблюдать FSD и public API через `index.ts`.
- Не использовать относительные импорты между FSD-слайсами.
- Для новых action controls использовать `wui-btn` из `@wui/common-library`; не делать клики на `wui-icon`, если действие является кнопкой.
- Не реализовывать backend-контракт priority в текущей части; priority оставить дефолтным как в ПБВ.
- Не переносить в текущий кейс Goose/завешенные линии, конференции, pin/lock и другие элементы со скриншотов, если они не нужны для базовой карточки трубок.
- Transfer входит в обсуждаемую модель WUI-5081, но должен быть вынесен в отдельную часть плана, если базовая карточка станет слишком большой для одного безопасного изменения.
- Не пытаться сохранить старую внутреннюю архитектуру `call-manager`, если ее проще заменить.
- Не сохранять старые `call-manager` / `call-queue` как параллельную совместимую реализацию для обычных трубочных вызовов. Они должны быть заменены или переписаны под новую карточку.
- Не ломать публичные маршруты и существующие public API без необходимости.
- Автотесты писать отдельным финальным шагом, после стабилизации контракта карточки.
- SIP/WebRTC сценарии проверять вручную.

## Дополнение от 2026-08-19 — transfer с консультацией (UI и поведение)

- Перестановка кнопок в `dialpad` при активированном `phoneTransferM`:
  - сверху (зелёная) — старт/кнопка consultation (раньше была disabled);
  - снизу (синяя) — blind transfer.
- После выбора blind transfer: поведение стандартное (как в текущей реализации).
- После старта consultation:
  - сверху (синяя) — merge, включается не раньше чем консультация стала CONNECTED;
  - снизу (красная) — cancel consultation, доступна всегда после начала consultation.
- Во время consultation `queue navigator` в левой части скрывается и вместо стрелок листинга очереди показывается merge-target (переводимый абонент A).
- Иконка `phoneTransferM` отображается рядом с `name` переводимого абонента A.
- В consultation правый `dialpad` работает как DTMF (для consultation-сессии), а не как ввод targetNumber.
- При отмене/неуспехе дозвона консультации: возвращаемся к стандартной карточке A (A остаётся на hold), справа active должен быть `queue`.
- На merge SUCCESS: выходим из consultation и теряем сессию с A (как в legacy), затем показываем “первую в очереди” по той же логике, учитывая ограничение “только 1 unhold на трубке” (выбранная сессия оказывается на hold).
- Если на целевой трубке уже активен другой transfer/consultation flow, перенос текущей consultation-сессии на эту трубку должен быть запрещён. Кнопка переноса между трубками визуально остаётся доступной, но по клику вместо переноса показывается notification с отказом.

## Дополнение от 2026-07-02 - функционал пустой карточки перед следующими состояниями

- UI базовой пустой карточки временно считается достаточным; дальнейшая работа по WUI-5081 должна сначала закрыть функциональный контракт пустого состояния.
- Вызов из dialpad пустой карточки должен использовать реальный механизм исходящего вызова: карточка, открытая из footer, позволяет набрать номер и запустить вызов кнопкой call.
- Клик по карточке ПБВ должен сразу инициировать исходящий вызов и открыть карточку. Если с абонентом уже есть наша сессия, нужно открыть карточку этой сессии вместо создания нового вызова.
- Физический ввод цифр с контроллера, не компьютерная клавиатура, должен автоматически открыть карточку выбранной или поднятой трубки, открыть dialpad и вводить цифры.
- Если dialpad уже содержит номер, новые цифры от контроллера должны вставляться в позицию курсора, как при работе с виртуальным вводом.
- Поднятие конкретной трубки должно открыть карточку именно этой трубки.
- Backspace нужен только для удаления перед курсором; Delete не требуется.
- Клик по истории вызовов только подставляет имя и номер и открывает dialpad, но не инициирует вызов автоматически.
- Dial buffer и выбранная правая панель остаются раздельными по трубкам.
- Runtime-сценарий отвала трубки при уже открытой карточке пока не обрабатывается. Если доступных трубок нет, footer disabled и карточка не открывается.
- Mute и volume нужно подключить к реальным audio/device/session операциям уже в ближайшей части. Состояние раздельное по трубкам и синхронизируется между состояниями карточки.
- Кнопка hangup в empty state остается disabled.
- После функционала пустой карточки нужно перейти к карточкам состояний вызова; очередь делать после них.

## Дополнение от 2026-07-02 - состояния вызова и очередь текущей трубки

- Следующая часть WUI-5081 должна закрыть основные состояния вызова: `incoming`, `outgoing`, `active`, `hold`, без реализации transfer.
- 2026-07-02: В ближайшем пуле WUI-5081 ничего по конференциям не делаем. Конференции остаются вне scope этой части и не должны влиять на модель состояний, очередь, footer sync и действия карточки.
- Структура карточки после empty state сохраняет общий layout: меняется левая часть карточки, а правая область переключается между панелями. Для empty используются `dialpad/history`, для сессии по умолчанию открывается `queue`, также доступен `dialpad`.
- `CallCardWindow` остается точкой сборки карточки, `CallCardLayout` держит общий shell, `CallCardEmptyState` отвечает только за левую часть пустого состояния. Следующая левая часть для сессии должна быть отдельным компонентом.
- Очередь карточки относится к текущей трубке. UI очереди должен быть сделан по мотивам history: список кнопок с иконкой, именем и номером, но с действиями выбора сессии.
- Клик по элементу очереди или переключение стрелками внутри карточки только меняет выбранную сессию для отображения. Это не должно автоматически делать `unhold`, `hold`, `answer` или менять активность сессии. Пользователь явно управляет состоянием отдельными кнопками.
- Выбранная в очереди сессия должна подсвечиваться. Стрелки в карточке и выбор в очереди должны синхронно менять и карточку, и выбранный элемент очереди.
- Если пользователь отвечает на входящий вызов, а на этой трубке уже есть активная сессия, текущая активная сессия переводится на hold, принятый входящий вызов становится активным.
- На будущее нужно рассмотреть сценарий `answer to hold`: при активном разговоре пользователь замечает новый входящий в очереди, выбирает его и отдельной кнопкой принимает сразу в hold, продолжая говорить с текущим абонентом. Этот сценарий не входит в ближайший пул правок.
- Footer должен быть синхронизирован с состояниями сессий: выбранная трубка окрашивается цветом выбранной/основной сессии, другая трубка в empty остается дефолтной, а при наличии сессии показывает соответствующую иконку и цвет статуса.
- Точную цветовую схему и токены для состояний нужно запросить у пользователя перед шагом синхронизации цветов. Базовая логика статусов сохраняется: `active` - зеленый, `hold` - оранжевый, `incoming/outgoing high` - красный, остальные входящие/исходящие - цвет по обычному приоритету/макету.

## Дополнение от 2026-07-03 - цветовая модель и раскладка кнопок карточки сессии

- Цветовая модель карточки сессии строится через `tone`, а не напрямую через сырой `sessionState`.
- `outgoing` всегда использует `waitcon`, независимо от priority. Это состояние исходящего набора, а не входящий high-priority сценарий.
- `active` всегда использует `callcon`.
- `hold` использует `waitcon`.
- `incoming` делится по priority: обычный входящий использует `warncon`, важный входящий использует `negcon`; для `negcon` текст на карточке должен быть белым.
- Иконки состояния зависят от стороны трубки:
  - исходящий: левая трубка `arrowNorthEastM`, правая трубка `arrowNorthWestM`;
  - входящий: левая трубка `arrowSouthWestM`, правая трубка `arrowSouthWestInvM`;
  - active/hold: левая трубка `phoneCallF`, правая трубка `phoneCallInvF`.
- В view-model карточки нужен отдельный `controlLayout`, чтобы UI не определял набор нижних кнопок по разрозненным условиям в шаблоне.
- Раскладка нижних кнопок:
  - empty: справа `history + dialpad`;
  - outgoing/incoming: слева `transfer to other handset`, справа `queue + dialpad`;
  - active/hold: слева `hold toggle + transfer to other handset`, справа `transfer toggle + queue + dialpad`;
  - transfer mode будет согласован и реализован отдельной частью.
- Dial buffer используется только для ручного набора в empty state и будущего transfer mode. При запуске вызова из empty state буфер очищается; входящий/исходящий/активный/hold показывают имя и номер только из карточки сессии, не через dial buffer.
- При успешном старте исходящего вызова из empty state, ПБВ или физической трубки правая панель сразу переключается на queue, не дожидаясь появления сессии в store.
- Если исходящий вызов стартовал при уже существующей очереди на трубке, после появления новой outgoing-сессии карточка должна выбрать именно последнюю набранную сессию и показать ее в левой части; уже существующие вызовы в очереди не должны оставаться выбранными.
- В incoming state в dialpad активны обе правые кнопки: зеленая трубка принимает выбранный входящий вызов на выбранную трубку, красная трубка отклоняет/завершает его. После принятия вызов переходит в active, зеленая трубка становится disabled до будущего transfer mode с введенным номером.
- Входящий вызов при открытии/выборе карточки всегда открывает правую панель `dialpad`, а не очередь.
- Queue отображает все сессии текущей трубки, включая выбранную. Клик по item только выбирает сессию для отображения и не выполняет `answer`, `hold`, `unhold` или `terminate`. Невыбранный item без фоновой заливки как history, цвет статуса получает только иконка. Выбранный item получает нейтральный active-фон `comp/tog/{tone}/twolinecon/bg/active/def`, не фон статуса/карточки; иконка остается active icon текущего `tog/{tone}`.
- Навигация стрелками по очереди поддерживает виртуальный empty-slot за границами списка. Для очереди из `N` сессий можно выйти на одну позицию до первой (`0 / N`) или на одну позицию после последней (`N + 1 / N`); дальше листание ограничено. Виртуальный empty-slot не включается в общее количество, показывает расширенное empty-состояние со стрелками и queue справа вместо history, позволяет набрать новый исходящий вызов, а после появления новой outgoing-сессии карточка выбирает ее. Клик по item в queue выбирает реальную сессию и закрывает виртуальный empty-slot. Новый incoming перебивает виртуальный empty-slot и выбирается по текущим правилам входящих.
- Когда последняя сессия трубки завершается и карточка возвращается в empty state, правая панель должна вернуться в дефолтный режим empty-состояния, а не оставаться пустой очередью.
- Footer-трубки синхронизируются с карточкой вызова. Если карточка открыта, выбранная трубка показывает статус выбранной реальной сессии; при virtual empty-slot выбранная трубка показывает свободное состояние. Если карточка закрыта, обе трубки показывают наиболее важную сессию своей очереди по приоритету: `incoming high` -> `incoming regular` -> `outgoing` -> `active` -> `hold` -> free. Невыбранная трубка всегда работает как индикатор по этому приоритету. Для выбранной трубки с сессией фон/бордер/текст/иконка берутся из active-токенов tone сессии. Для невыбранной трубки с сессией фон остается default/inactive, статусным цветом красится только иконка, текст остается handset inactive text token.
- На одной трубке одновременно может быть только одна active/`CONNECTED` сессия. Если несколько исходящих на одной трубке были приняты абонентами и стали `CONNECTED`, активной остается выбранная/актуальная сессия, остальные connected-сессии этой же трубки переводятся в hold. На разных трубках одновременно может оставаться по одной active-сессии.
- Конференции по-прежнему не входят в текущую часть WUI-5081.

## Дополнение от 2026-07-03 - слепой перевод в карточке вызова

- Следующая часть WUI-5081 должна реализовать только слепой перевод. Полноценный перевод с сопровождением, merge-консультации и конференции не входят в эту часть.
- Перевод работает из `active` или `hold` source-вызова. Source-сессия фиксируется в момент включения режима перевода кнопкой `phoneTransferM`.
- Повторный клик по `phoneTransferM` отменяет режим перевода. Закрытие карточки крестиком также сбрасывает режим перевода.
- Если source-сессия завершилась или перестала быть доступной, режим перевода должен быть сброшен.
- В режиме перевода dialpad используется для ввода номера цели перевода, а не для DTMF.
- Слепой перевод через dialpad: пользователь включает `phoneTransferM`, открывается dialpad, пользователь вводит номер, справа от dialpad активируется кнопка слепого перевода. По клику source-вызов переводится на введенный номер. На успехе source уходит из карточки; на ошибке ошибка логируется в консоль, режим перевода и введенный номер остаются открытыми для повтора.
- Слепой перевод через очередь: пользователь включает `phoneTransferM`, открывается очередь текущей трубки, клик по элементу очереди выбирает цель перевода и открывает dialpad с подставленным номером цели. После клика по кнопке слепого перевода выполняется перевод source на выбранную цель.
- Target слепого перевода может быть просто номером без нашей локальной сессии. В таком сценарии карточка вызывает перевод source-сессии на `targetNumber`; отдельная сессия с target не создается.
- В режиме перевода клик по элементу очереди выбирает target, а не переключает отображаемую source-сессию карточки.
- Если целью выбрана существующая сессия из очереди и session API позволяет передать `toSession`, можно использовать перевод с завершением обеих наших сессий на успехе. Если перевод падает, обе сессии не должны принудительно завершаться карточкой.
- Нельзя выбирать source-сессию как target перевода.
- Кнопка перевода с сопровождением отображается в dialpad, но в этой части всегда disabled и без логики.
- В dialpad в режиме перевода правая кнопка слепого перевода сохраняет обычную иконку звонка и текущую call-кнопку. Кнопка перевода с сопровождением использует иконку `mergeM`, цвет иконки `comp/btn/brandcon/num/icon/def` и фон `btn-brandcon-num-bg`; если токена еще нет, допускается временный fallback до добавления токена.
