# Кейс: WUI-5214 — История вызовов 3.0 по аналогии со справочником

## Описание текущей части кейса

Нужно перевести историю вызовов на новый табличный UI по образцу `PhoneBookPanel`: с `widget-header`, поиском, фильтрами на `my-btn`, сортировкой, пагинацией и строковым действием, которое открывает `call card` и подставляет номер в `dialpad`. При этом нужно переиспользовать существующие данные истории и часть legacy-логики, а старые компоненты истории после миграции удалить.

# План реализации: История вызовов 3.0

## Шаг 1: Подготовить модель отображения и контракт панели

- **Описание:** Определить и реализовать view-model для строк истории под новый `wui-data-table`: вычисление отображаемого типа вызова, номера, имени, даты/времени, длительности, наличия записи, иконки типа и пустого action-столбца. На этом же шаге подготовить клиентские фильтры `все / входящие / исходящие / пропущенные / частые`, поиск и клиентскую сортировку по согласованным полям, не меняя еще точки подключения страницы.
- **Файлы для изменений:**
  - `src/entities/call-history/model/*`
  - `src/entities/call-history/index.ts`
  - при необходимости новые типы/mapper внутри слайса `call-history`
- **Ожидаемый результат:** Есть изолированная модель данных для нового табличного UI истории, которая переиспользует текущий store истории и покрывает все будущие колонки и фильтры.
- **Проверка:** Локальная проверка типов целевого модуля; ручная верификация вычислений на основе существующих записей истории в devtools/через UI после подключения на следующем шаге.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 2: Собрать новый `CallHistoryPanel` в `widgets`

- **Описание:** Реализовать новый виджет истории по образцу `PhoneBookPanel`: `widget-header`, поиск, группа фильтров на `my-btn`, `wui-data-table`, сортировка, пагинация, фиксированное количество строк в зависимости от `isHeaderHidden`, пустой action-столбец со стрелкой как в справочнике. Подключить поведение клика по строке к сценарию справочника: открыть `call card` и заполнить `dialpad` номером/именем.
- **Файлы для изменений:**
  - `src/widgets/call-history/ui/CallHistoryPanel.vue`
  - `src/widgets/call-history/index.ts`
  - при необходимости вспомогательные private-файлы внутри `src/widgets/call-history/`
- **Ожидаемый результат:** Новый `CallHistoryPanel` функционально и визуально повторяет паттерн `PhoneBookPanel`, но использует историю вызовов и согласованный набор колонок/фильтров.
- **Проверка:** Ручная проверка в UI: поиск, переключение фильтров, сортировка, пагинация, клик по строке, отображение конференций с иконкой `userGroupM`.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет

## Шаг 3: Переключить все точки входа на новый виджет и удалить legacy-историю

- **Описание:** Подключить новый `CallHistoryPanel` во все актуальные места использования по аналогии со справочником: через `src/widgets`, `workspace-widget-registry` и связанные exports. Удалить `HistoryPage.vue`, `WorkspaceHistoryWidget.vue`, старый `CallHistoryTable.vue` и `CallHistoryRow.vue`, а также почистить импорты/реэкспорты, которые больше не нужны.
- **Файлы для изменений:**

  - `src/pages/main/ui/index.ts`
  - `src/pages/main/ui/HistoryPage.vue`
  - `src/pages/main/ui/workspace/workspace-widgets/index.ts`

  - `src/widgets/call-history/ui/CallHistoryTable.vue`
  - `src/entities/call-history/ui/CallHistoryRow.vue`

- **Ожидаемый результат:** В приложении остается единая новая реализация истории вызовов без legacy-дублей, а workspace использует ее как основной виджет.
- **Проверка:** Ручная навигация по workspace/history-сценариям, проверка отсутствия сломанных импортов.
- **Коммит после шага:** Да
