# Кейс: CI — опциональная stage-сборка без проверки контроллера

## Описание текущей части кейса

Добавить в GitLab CI опциональную джобу `.deb` со stage-сборкой (`npm run build:stage`), чтобы вход не требовал контроллер.

# План реализации: опциональный build-deb-stage

## Шаг 1: Добавить опциональную джобу build-deb-stage

- **Описание:** В якоре `.deb_prepare` вынести npm-скрипт сборки в переменную `FRONTEND_BUILD_CMD` с дефолтом `build`. Добавить джобу `build-deb-stage`: `FRONTEND_BUILD_CMD=build:stage`, `when: manual`, `allow_failure: true`, те же артефакты, что у `build-deb`.
- **Файлы для изменений:** `.gitlab-ci.yml`
- **Ожидаемый результат:** В пайплайне появляется ручная джоба `build-deb-stage`. Если её не запускать, пайплайн не блокируется. Production-джобы по-прежнему собирают `npm run build`.
- **Проверка:** Просмотр diff `.gitlab-ci.yml`; при наличии `gitlab-ci-local` — валидация конфига.
- **Коммит после шага:** Да
- **Нужно ли обновить project wiki:** Нет
