# WUI-5609 — Странный поиск в справочнике

## Исходная задача

В результатах поиска по абонентам отображаются абоненты, не соответствующие запросу.

Env: 192.168.136.91, dealing-console 3.0.0-alpha.12, РТУ 2.3.2-71_Smolensk.

Шаги: Справочник → поиск `99`.
ОР: нет совпадений.
ФР: показываются 1009, 9003.

Note QA: если бы был substring по номерам 9001–9009, ожидались бы все/многие из них, а не один; поведение в окне выбора абонентов (ПБВ / завешенные) отличается (есть видео).

## Уточнения пользователя

- 2026-09-07: сначала обсудить модель поиска; правки после согласования. Справочник.
- Модель: ФИО + телефон + email, contains; модалки — другой кейс.
- `SearchText` матчит в т.ч. guid — не использовать.
- 2026-09-07: запрос выглядел «странно» (`Filters%5B0%5D...`) — причина в `URLSearchParams`, который кодирует скобки; web шлёт `Filters[0].PropertyName` без encoding скобок. Поправили `contactsQueryToString`.
- 2026-09-07: делаем **как на web-клиенте + email**: параллельные GET по полям + merge по id; цифры → телефоны (+ email), текст → names (+ email); пагинация поиска клиентская.
- 2026-09-07: **`FilterLogicOperator=or` не работает** — только multi-request + merge.
- 2026-09-07: **внешние контакты → полностью на бэк, IndexedDB уходит.** Создание: проверка группы для внешних → если нет, фронт создаёт группу `name: 'externalContact'`, `type: 'user'` → кладёт контакт туда → в ПБВ показываем только группы с `name !== 'externalContact'`. Реализация миграции — **отдельный тикет**, не WUI-5609.

- В WUI-5609 правим только поиск **справочника**.
- Модалки выбора / миграция внешних с IDB на бэк — отдельные тикеты.
- Не использовать `SearchText` / `FilterLogicOperator=or` для поиска справочника.
