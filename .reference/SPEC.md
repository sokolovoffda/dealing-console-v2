# Спецификация проекта "Дилинговый пульт РТУ"

## 1. Общее описание проекта

### 1.1. Назначение и цели

**Дилинговый пульт РТУ** (Dealing Console RTU) — кроссплатформенное абонентское приложение для речевого дилинга, предназначенное для управления телефонными звонками, конференциями и коммуникациями в банковской и биржевой торговле.

**Контекст применения:**
Система речевого дилинга для банковских и биржевых трейдеров, брокеров. Пользователи совершают брокерские операции по телефонии, осуществляя торговые сделки, обмен информацией о котировках, согласование условий сделок и другие критические для финансового рынка операции.

**Основные цели проекта:**
- Предоставление надежного и производительного интерфейса для обработки десятков одновременных вызовов
- Реализация функционала "завешивания" звонков для одновременной работы с множеством контрагентов
- Интеграция с аппаратными контроллерами для расширенного управления (Goose, Handset, Hub)
- Поддержка как веб-версии (PWA), так и десктопного приложения (Electron)
- Обеспечение высокого качества связи и низкой задержки для критичных финансовых операций
- Поддержка работы с до 16 активных завешенных вызовов одновременно на протяжении всего рабочего дня

**Принципиальное отличие от классической телефонии:**
В отличие от стандартной обработки вызовов, где пользователь может говорить только с одним абонентом (остальные на удержании), консоль трейдера позволяет одновременно разговаривать со всеми завешенными линиями, используя громкую связь (спикер) и функцию Voice Activity Detection (VAD) для визуальной индикации активности на линии.

### 1.2. Целевая аудитория

- **Основные пользователи:** 
  - Банковские трейдеры
  - Биржевые трейдеры
  - Брокеры
  - Финансовые дилеры
  - Операторы рынка ценных бумаг
- **Контекст использования:** Трейдинг-деск, торговые залы банков, брокерские компании, финансовые организации
- **Сценарии использования:** Брокерские операции по телефонии, согласование сделок, обмен котировками, консультации с контрагентами
- **Требования к оборудованию:** Десктопные компьютеры с поддержкой WebRTC, опционально — аппаратные контроллеры Сател (Goose модули, телефонные трубки, гарнитуры)

### 1.3. Основные возможности

#### 1.3.1. Завешенные линии (Pinned Calls)

- **До 16 активных завешенных вызовов одновременно** — поддержка длительного поддержания активных звонков на протяжении всего рабочего дня
- **Громкая связь (спикер)** — одновременное прослушивание всех завешенных линий
- **Voice Activity Detection (VAD)** — автоматическое обнаружение речевой активности для визуальной индикации (мигание кнопки при активности контрагента)
- **Индивидуальное управление громкостью** — регулировка уровня звука для каждой завешенной линии отдельно
- **Управление микрофоном на линии** — включение/отключение микрофона для конкретной завешенной линии (PTT - Push-to-Talk)
- **Индикация статуса линии:**
  - Название контрагента или телефонный номер
  - Статус линии (активная/сброшенная)
  - Уровень громкости с возможностью регулировки
  - Статус микрофона (красный/зачеркнут — выключен, зеленый — включен)
  - Индикация активности через мигание при VAD
- **Быстрое переключение между линиями** — переключение звонка со спикера на трубку и обратно

#### 1.3.2. Групповые функции

- **Групповой вызов (кнопка группового вызова):**
  - **Режим 1 - Предварительно запрограммированная группа:**
    - Кнопка предварительно запрограммирована для определенных спикер-каналов (например, первых четырех)
    - Нажатием на кнопку активируется микрофон ГГС (гусиной шеи) для этих спикер-каналов
    - Голосовая информация, которую говорит пользователь в микрофон ГГС, слышат контрагенты, завешенные на этих каналах
    - Повторным нажатием кнопки группового вызова микрофон сбрасывается со всех спикер-каналов
  - **Режим 2 - Выборочная активация:**
    - Нажатием активируется функционал группового вызова
    - Пользователь дополнительно выбирает нажатием на определенные линии спикер-канала тех контрагентов, которые будут его слышать (например, первый спикер-канал, третий и четвертый)
    - Активируется микрофон ГГС для выбранных линий
    - При повторном нажатии на кнопку группового вызова микрофон сбрасывается
- **Конференции** — добавление участников к текущему звонку или завешенной линии нажатием кнопки конференции

#### 1.3.3. Управление звонками

- Управление входящими и исходящими звонками
- Создание и управление конференциями с масштабируемым количеством участников
- Переадресация звонков (условная, каскадная, на группы, голосовая почта)
- Перехват и мониторинг звонков (barge-in, whisper)
- Перевод звонков (blind, attended, consultation transfer)
- Подхват входящих звонков коллег
- Возможность вклиниваться в разговор коллег (1-2 касания)

#### 1.3.4. Управление медиа-устройствами

- Одновременное использование микрофона и двух трубок
- Использование микрофона + трубки + гарнитуры
- Индикаторы активности устройств (активная трубка подсвечивается зеленым)
- Быстрое переключение между трубками
- Быстрое переключение с трубки на спикер-канал и обратно

#### 1.3.5. Мониторинг и статусы

- Мониторинг линий коллег — просмотр статуса линий (свободна/занята) с отображением контакта
- Переключение между вкладками с завешенными линиями
- Установка переадресации с устройства

#### 1.3.6. Дополнительные функции

- Управление контактами и телефонной книгой с интеграцией LDAP/Active Directory
- История звонков с расширенным поиском и фильтрацией
- Очереди звонков с приоритетами
- Интеграция с аппаратными контроллерами (goose, handset, LED индикаторы)
- Инстант-мессенджер для обмена сообщениями
- Настройка переадресации с временными правилами
- Черные и белые списки с поддержкой regex-паттернов
- Управление группами контактов (статические и динамические)
- Система записи переговоров (опционально с возможностью прослушивания)

### 2.2. Архитектура приложения

Проект использует **Feature-Sliced Design (FSD)** архитектуру:

```
src/
├── app/              # Инициализация приложения, роутинг, layout
├── pages/            # Страницы приложения
├── widgets/          # Крупные составные блоки UI
├── features/         # Бизнес-функции (user stories)
├── entities/         # Бизнес-сущности
└── shared/           # Переиспользуемый код
    ├── ui/           # UI компоненты
    ├── utils/        # Утилиты
    ├── composables/  # Vue composables
    ├── services/     # Сервисы
    ├── jssip/        # WebRTC/SIP логика
    ├── controller/   # Интеграция с контроллерами
    └── auth/         # Аутентификация
```

**Принципы организации:**
- **Entities** — бизнес-сущности (call-session, conference, contact, call-history)
- **Features** — пользовательские сценарии (pinned-calls, refer-call, search-bar)
- **Widgets** — составные UI блоки (call-manager, pinned-calls, phone-book)
- **Shared** — общий код, не привязанный к бизнес-логике

### 2.3. Интеграции

#### 2.3.1. RTUM Backend

**Backend сервер:** RTUM (rtum.satel.org) — кастомный SIP-сервер (не стандартный Asterisk/FreeSWITCH)

**API эндпоинты:**
- `/api/user/login` — аутентификация
- `/api/user/refresh-token` — обновление токена
- `/api/user/change-password` — смена пароля
- `/api/user/contacts` — получение контактов, включая фильтрацию по `groupId`
- `/api/Group/list` — список backend-групп контактов
- `/api/*` — общие API запросы
- `/selector` — селектор контактов
- `/im` — WebSocket для инстант-мессенджера
- `/prompt` — WebSocket для промптов
- `/sip` — WebSocket для SIP сигнализации

**Проксирование:** Vite dev-сервер проксирует запросы к различным окружениям (dev, stage, production)

#### 2.3.2. Аппаратные контроллеры

**Типы устройств:**
- **Goose** — аппаратный модуль, содержащий микрофон типа "гусиная шея" (ГГС) и набор из 8 клавиш для привязки контактов с LED подсветкой
- **Handset** — телефонные трубки с LED индикаторами
- **Hub** — центральный хаб контроллера с LED линией

**Протокол связи:**
- **WebSocket** на `ws://127.0.0.1:8765` (локальное подключение)
- JSON-протокол с командами и событиями
- Поддержка регистрации устройств, обработки нажатий кнопок, управления LED

**Функции:**
- Привязка контактов к кнопкам контроллера
- Визуальная индикация статуса контактов через LED (красный, зеленый, синий, оранжевый, белый)
- Управление яркостью и эффектами подсветки
- Получение информации о сетевых интерфейсах и модулях

## 3. Функциональные требования

### 3.1. Управление звонками

#### 3.1.1. Входящие звонки

- Отображение входящего звонка с информацией о контакте
- Принятие/отклонение звонка
- Автоматический ответ для конференций и закрепленных контактов
- Обработка переадресации согласно правилам
- Интеграция с очередями звонков

#### 3.1.2. Исходящие звонки

- Набор номера через клавиатурную панель
- Выбор медиа-устройства перед звонком
- Быстрый набор из телефонной книги
- Вызов из закрепленных контактов
- Вызов из истории звонков

#### 3.1.3. Активные звонки

- Удержание звонка (hold)
- Переключение между звонками
- Перевод звонка:
  - **Blind transfer** — перевод без ожидания ответа
  - **Attended transfer** — перевод с ожиданием ответа
  - **Consultation transfer** — консультация перед переводом
- Перехват звонка (interception):
  - Перехват звонка другого пользователя
  - Мониторинг/подслушивание
  - Barge-in (вмешательство в звонок)

#### 3.1.4. Подхват звонков (Pickup)

- **Directed pickup** — подхват конкретного звонка по номеру
- **Group pickup** — подхват звонка группы
- Подхват через аппаратный контроллер

### 3.2. Конференции

#### 3.2.1. Создание конференций

- Создание из тет-а-тет звонка
- Создание из группы контактов
- Создание пустой конференции с последующим добавлением участников
- **Добавление участников к текущему звонку или завешенной линии** — нажатием кнопки конференции пользователь может добавить еще одного участника
- Масштабируемое количество участников (динамическое масштабирование)

#### 3.2.2. Управление конференцией

- Просмотр списка участников с их статусами
- Отключение микрофона участников (mute)
- Исключение участников (kick)
- Запись конференции (серверная)
- Блокировка входа новых участников (lock)
- Управление громкостью отдельных участников
- Глобальное управление громкостью всех закрепленных звонков

#### 3.2.3. Участие в конференции

- Автоматический ответ для исходящих конференций
- Переключение между конференциями
- Выход из конференции с сохранением остальных участников

### 3.3. Контакты и телефонная книга

#### 3.3.1. Управление контактами

- Просмотр списка контактов
- Поиск контактов (полнотекстовый поиск)
- Фильтрация контактов
- Интеграция с LDAP/Active Directory
- Локальное редактирование контактов (если поддерживается backend)

#### 3.3.2. Группы контактов

- Статические группы
- Динамические группы
- Групповой звонок всем участникам
- Создание конференции из группы
- Управление микрофоном и громкостью группы
- Backend-группы используются как источник вкладок панели быстрого вызова

#### 3.3.3. Вкладки панели быстрого вызова (Contact Tabs)

- Вкладка соответствует backend-группе из `/api/Group/list`
- Backend является source of truth для состава и порядка групп
- Базовая модель вкладки: `id`, `groupGuid`, `name`, `order`, `enabled`
- Стор вкладок хранит только группы, без контактов всех групп
- Контакты активной группы загружаются отдельно виджетом панели быстрого вызова
- Повторная инициализация защищена от лишних запросов к `/api/Group/list`
- Новая логика не использует старые `loadByPreferences()` и `saveByPreferences()`

#### 3.3.4. Панель быстрого вызова (Workspace Contacts Widget)

- Панель отображает вкладки backend-групп и контакты активной группы
- Активная группа определяется через `useContactTabs().activeTab.groupGuid`
- Контакты загружаются через `/api/user/contacts` с параметром `groupId`
- Контакты кэшируются по `groupGuid`, чтобы повторное открытие вкладки не делало лишний запрос
- Для карточки контакта отображаются иконка пользователя, номер и имя
- Номер берется с fallback-цепочкой: `internalNumber`, `mobilePhone`, `email`, `pServed`
- Карточка поддерживает базовые состояния `online` и `offline` по SIP/BLF presence
- Цвета карточки описаны токенами `priority -> presence -> colors`, сейчас реализован `default` priority
- Offline-состояние не задается общей opacity всей карточки, а использует отдельные цвета фона, иконки, номера и имени

#### 3.3.5. Привязка контактов (Binding Contacts)

- Привязка контактов к кнопкам модуля Goose (до 8 контактов на модуль)
- Привязка контактов к кнопкам других аппаратных контроллеров
- Настройка горячих клавиш для быстрого набора
- Визуальная индикация статуса контактов через LED кнопок модуля Goose
- Редактирование привязок контактов к кнопкам

### 3.4. История звонков

#### 3.4.1. Просмотр истории

- Список всех звонков (входящие, исходящие, пропущенные)
- Информация о звонке: контакт, время, длительность, тип
- Локальный кэш для быстрого доступа
- Пагинация для больших объемов данных

#### 3.4.2. Поиск и фильтрация

- Полнотекстовый поиск по истории
- Расширенные фильтры:
  - По дате/времени
  - По контакту
  - По типу звонка
  - По статусу
- Экспорт истории звонков

### 3.5. Переадресация звонков

#### 3.5.1. Типы переадресации

- **Условная переадресация:**
  - По занятости (BUSY)
  - По недоступности (UNAVAILABLE)
  - По отсутствию ответа (NO_ANSWER)
  - По всем условиям (ALL)

- **Каскадная переадресация** — несколько попыток с приоритетами
- **Переадресация на группу** — переадресация на группу контактов
- **Голосовая почта** — переадресация на голосовую почту

#### 3.5.2. Временные правила

- Расписание переадресации (permanent schedule)
- Специальные расписания (special schedule items)
- Шаблоны расписаний (timetable templates)

#### 3.5.3. Сервисы переадресации

- Переадресация (Forward)
- Не беспокоить (DoNotDisturb)
- Черные/белые списки (BlackWhiteList)
- Голосовая почта (VoiceMailForwarding)
- Следуй за мной (FollowMe)
- IVR

### 3.6. Очереди звонков

- **FIFO** — первый пришел, первый обслужен
- **Приоритетная очередь** — обработка по приоритетам
- Отображение очереди в реальном времени

### 3.7. Закрепленные звонки (Pinned Calls / Завешенные линии)

**Назначение:**
Система завешенных линий является ключевой функциональностью для трейдеров, позволяя одновременно работать с множеством контрагентов в течение всего рабочего дня.

**Основные характеристики:**
- **До 16 активных завешенных вызовов одновременно** — поддержка длительного поддержания звонков в активном состоянии
- **Работа в течение всего рабочего дня** — звонки остаются активными до принудительного завершения пользователем или контрагентом
- Быстрый доступ к важным контактам и контрагентам
- Мониторинг активных звонков в реальном времени
- Управление параллельными звонками с возможностью одновременного прослушивания

**Функции завешенных линий:**

#### 3.7.1. Отображение информации на кнопке спикер-канала

- **Название линии** или телефонный номер контрагента
- **Статус линии:** активная или сброшенная (в момент сброса)
- **Индикатор уровня громкости** с возможностью индивидуальной регулировки для каждой линии (необходимо, т.к. у каждой линии может быть разный уровень из-за разных каналов связи)
- **Индикатор микрофона:**
  - Красный или зачеркнут — микрофон выключен
  - Зеленый — микрофон включен
  - Нажатие на индикатор включает/отключает микрофон на конкретной линии
- **Мигание кнопки при активности** — индикация речевой активности контрагента через Voice Activity Detection (VAD)

#### 3.7.2. Voice Activity Detection (VAD)

**Описание:** Автоматическое обнаружение речевой активности на завешенных линиях для визуальной индикации активности контрагента.

**Применение:**
- Мигание кнопки спикер-канала при начале речи контрагента
- Информирование пользователя об активности на линии даже при уменьшенной громкости
- Возможность быстро увеличить громкость при мигании для прослушивания важной информации

**Техническая реализация:**
- Анализ аудиопотока в реальном времени
- Определение порога речевой активности
- Визуальная обратная связь через мигание кнопки

#### 3.7.3. Управление завешенными звонками

- Добавление контакта на спикер-канал (завешивание звонка)
- Удаление контакта из завешенных
- Индивидуальное управление громкостью для каждой линии
- Управление микрофоном на конкретной линии (включение/отключение)
- Переключение звонка со спикера на трубку и обратно
- Завершение завешенного звонка

#### 3.7.4. Рабочий процесс трейдера

1. **Начало рабочего дня:** Пользователь входит в консоль, подгружается преднастроенный интерфейс
2. **Завешивание линий:** Пользователь обзванивает контрагентов и завешивает их на спикеры (каналы громкой связи)
3. **Работа с линиями:** В течение дня пользователь:
   - Прослушивает активные линии
   - Реагирует на мигание кнопок (VAD индикация)
   - Управляет громкостью для комфортной работы
   - Включает микрофон для ответа конкретному контрагенту
   - Переключает звонки между спикером и трубкой по необходимости
4. **Завершение работы:** Звонки остаются активными или завершаются принудительно

### 3.8. Аппаратные контроллеры

#### 3.8.1. Goose модули

**Описание устройства:**
Goose — аппаратный модуль, который включает:
- **Микрофон типа "гусиная шея" (ГГС)** — микрофон-подвеска для работы в трейдинг-деске, используемый в режиме PTT (Push-to-Talk)
- **Набор из 8 клавиш** — программируемые кнопки для быстрого набора и управления контактами
- **LED подсветка кнопок** — визуальная индикация статуса контактов (красный, зеленый, синий, оранжевый, белый, черный)

**Функции:**
- Привязка контактов к кнопкам (до 8 контактов на модуль)
- LED подсветка кнопок для визуальной индикации статуса контактов
- Управление яркостью подсветки (0-255)
- Эффекты анимации (мигание с настраиваемой частотой)
- Индикация активности через изменение цвета LED
- Интеграция с микрофоном ГГС для управления речью в режиме PTT

**Использование:**
- Быстрый набор контактов через нажатие на запрограммированную кнопку
- Визуальный мониторинг статуса контактов (занят, свободен, в звонке)
- Управление микрофоном ГГС для конкретных завешенных линий
- Групповое управление микрофоном через кнопки линий

#### 3.8.2. Handset (телефонные трубки)

- LED индикаторы на трубках
- Управление статусом через LED
- Интеграция с медиа-устройствами

#### 3.8.3. Hub (центральный хаб)

- LED линия для общей индикации
- Управление режимами подсветки

#### 3.8.4. Сетевые функции

- Получение информации о модулях контроллера

#### 3.10.2. Расширенное использование устройств

**Одновременное использование устройств:**
- Микрофон + две трубки
- Микрофон + трубка + гарнитура
- Комбинированные конфигурации для работы с несколькими контрагентами

**Индикаторы активности устройств:**
- Активная трубка подсвечивается зеленым цветом
- Визуальное отображение статуса всех подключенных устройств
- Быстрая идентификация активного устройства

**Быстрое переключение между устройствами:**
- Переключение с одной трубки на другую (при разговоре с разными контрагентами)
- Переключение с трубки на спикер-канал:
  - Пользователь видит мигающую кнопку спикер-канала (VAD индикация)
  - Нажимает на мигающий спикер-канал
  - Нажимает кнопку трубки на поле активности трубок
  - Звонок переключается со спикер-канала на трубку для приватного разговора
- Переключение со спикера обратно на трубку:
  - Во время активного звонка на трубке
  - Нажатие на свободную линию на поле спикер-каналов
  - Звонок переключается с трубки на спикер-канал и остается висеть активным

**Управление микрофоном гусиной шеи (ГГС):**
- Микрофон ГГС встроен в модуль Goose
- Режим "рации" (PTT - Push-to-Talk) — микрофон работает только при нажатии аппаратной кнопки "микрофон"

- Управление микрофоном для отдельных завешенных линий через пиктограммы на плитках завешенных вызовов
- Возможность управления микрофоном ГГС через кнопки клавиш линий модуля Goose (маппинг один-в-один)

## 5. Технические детали

### 5.1. WebRTC и SIP регистрация

#### 5.1.1. SIP регистрация

- **Протокол:** SIP over WebSocket
- **Интервал регистрации:** 120 секунд (стандартные интервалы)
- **Автоматическое обновление:** Регистрация обновляется до истечения
- **Обработка событий:**
  - `registered` — успешная регистрация
  - `unregistered` — отмена регистрации
  - `registrationFailed` — ошибка регистрации
  - `registrationExpiring` — истечение регистрации
  - `connected` — подключение к серверу
  - `disconnected` — отключение от сервера

#### 5.1.2. WebRTC звонки

- **Аудио кодек:** WebRTC встроенная обработка (Opus по умолчанию)
- **Видео:** Не поддерживается (только аудио)
- **ICE серверы:** Конфигурация с сервера
- **Медиа ограничения:**
  - Выбор микрофона через `deviceId`
  - Только аудио (`video: false`)

#### 5.1.3. Управление сессиями

- Хранение активных сессий в `useSessionStore`
- Привязка сессий к медиа-устройствам
- Управление состоянием звонков (connecting, active, on hold, ended)
- Обработка событий сессий через `useSessionEventListener`

### 5.2. Управление состоянием (Pinia)

#### 5.2.1. Stores

- **useSessionStore** — управление активными звонками
- **useConferenceState** — состояние конференций
- **useContactStore** — контакты и телефонная книга
- **useContactTabs** — вкладки панели быстрого вызова на базе backend-групп
- **useContactStatusState** — SIP/BLF статусы контактов и линий
- **usePinnedCallsStore** — закрепленные звонки
- **useForwardingSettingsStore** — настройки переадресации
- **useAppStore** — общее состояние приложения
- **usePreferencesStore** — пользовательские настройки
- **useDevicesStore** — медиа-устройства и контроллеры

#### 5.2.2. Проблемы и риски

- **Синхронизация состояния** — возможны проблемы с синхронизацией между компонентами
- **Race conditions** — возможны гонки при параллельных операциях
- **Сложность управления** — много параллельных сессий и конференций усложняют состояние

#### 5.2.3. Модель вкладок и контактов активной группы

**useContactTabs:**
- Инициализируется на уровне `LayoutApplication.vue`, чтобы вкладки были доступны всем экранам после старта приложения
- Получает группы через `useContactStore().fetchAllGroups(false)`
- Хранит `tabs`, `activeTabId`, `loading`, `error`, `isInitialized`
- Предоставляет getters `sortedTabs`, `enabledTabs`, `activeTab`, `hasTabs`
- `initTabs()` не выполняет повторный backend-запрос после успешной инициализации без `force`
- `refreshTabs()` принудительно перечитывает backend-группы и сохраняет активную вкладку, если ее `groupGuid` остался в ответе
- Не хранит контакты внутри вкладок и не отвечает за SIP/BLF подписки

**useWorkspaceGroupContacts:**
- Загружает контакты только для активной backend-группы
- Использует `Map<groupGuid, Contact[]>` как локальный cache уровня виджета
- Загружает контакты пачкой до 100 записей на страницу
- При ошибке очищает cache текущей группы и показывает сообщение об ошибке в виджете

**Граница ответственности:**
- `entities/settings/contact-tabs` отвечает за список и выбор вкладок-групп
- `widgets/workspace-widget` отвечает за загрузку контактов активной группы, визуальную карточку и SIP/BLF подписку
- Preferences не являются источником правды для нового потока вкладок панели быстрого вызова

#### 5.5.2. Процесс входа

1. Пользователь вводит логин, пароль, домен
2. POST запрос на `/api/user/login`
3. Получение access и refresh токенов
4. Сохранение токенов и информации о пользователе

#### 5.5.3. Обновление токена

#### 5.5.4. Защита маршрутов

- `beforeEachHook` проверяет аутентификацию
- Публичные маршруты помечаются `meta.isPublic`
- Редирект на `/login` для неавторизованных пользователей

### 5.6. WebSocket соединения

#### 5.6.1. Типы WebSocket

- **SIP WebSocket** — `/sip` для SIP сигнализации
- **IM WebSocket** — `/im` для инстант-мессенджера
- **Prompt WebSocket** — `/prompt` для промптов
- **Controller WebSocket** — `ws://127.0.0.1:8765` для контроллеров

#### 5.6.2. Переподключение

- **Exponential backoff** — стратегия переподключения с увеличивающимися интервалами
- Автоматическое переподключение для контроллера (каждые 5 минут в production)
- Синхронизация состояния после переподключения

### 5.7. Presence (статусы присутствия)

- **Rich presence** — расширенные статусы (онлайн, в звонке, недоступен, перерыв)
- **Подписка на статусы** — SIP SUBSCRIBE для получения статусов других пользователей
- **Обновление статусов** — через NOTIFY сообщения
- **Визуальная индикация** — отображение статусов в интерфейсе и на контроллере
- **Карточки панели быстрого вызова** — online/offline определяется по `useContactStatusState().contactStatuses[internalNumber].registered`
- **Подписка активной группы** — `useWorkspaceContactStatusSubscription` подписывает internalNumber контактов активной группы после SIP-регистрации
- **Параметры подписки** — batch size 16, задержка между пачками 1000 мс, срок подписки 5 минут
- **Защита от дублей** — внутри widget-level подписки хранится набор уже подписанных internalNumber

- Использование клавиатурной панели (KeyboardPad) для отправки DTMF
- Интеграция с IVR системами
- Автоматическая передача DTMF при наборе

## 11. Известные проблемы и баги

### 11.1. Активные проблемы (в работе)

#### 11.1.1. Проблемы с микрофоном ГГС (гусиная шея)

**WUI-3825** — Проблема логики работы микрофона ГГС в режиме "рации" (PTT)
- **SD заявка:** SD 91170
- **Описание:** В режиме рации (PTT) микрофон ГГС (встроенный в модуль Goose) начинает работать без нажатия аппаратной кнопки "микрофон" при переключении между завешенными вызовами. При включении микрофона ГГС одного завешенного вызова (пиктограммой на плитке) он начинает работать в эту завешенную линию без нажатия аппаратной кнопки "микрофон" на модуле Goose. После однократного нажатия кнопки "микрофон" работа нормализуется, но при переключении на другой завешенный вызов проблема повторяется. Необходимо сделать, чтобы в режиме "рации" микрофон ГГС всегда работал только при нажатии аппаратной кнопки "микрофон" на модуле Goose.
- **Статус:** Анализ
- **Планируемая версия:** 2.8.14
- **Срок:** (не указан)

**WUI-3826** — Доработка отображения статуса микрофона ГГС
- **SD заявка:** SD 91174
- **Описание:** Требуется отображение актуального статуса микрофона ГГС (гусиной шеи) цветом в пиктограмме завешенного вызова. Серая область слева должна отображать статус: зеленый цвет фона - микрофон работает, красный - микрофон не работает. Цвет нужен для облегчения идентификации включенного микрофона. В идеальном варианте с кастомизацией цвета.
- **Статус:** Анализ
- **Планируемая версия:** 2.8.14
- **Срок:** (не указан)

**WUI-3827** — Доработка отображения статуса говорящего завешенного вызова ГГС
- **SD заявка:** SD 91175
- **Описание:** Требуется отображение статуса говорящего завешенного вызова ГГС (абонента завешенного вызова) оранжевой рамкой с тайм-аутом гашения после окончания речи в 3 сек. Без задержки непонятно какой из завешенных говорил, а цветная рамка помогает быстрее идентифицировать говорившего. В идеальном варианте с кастомизацией цвета рамки и временем задержки.
- **Статус:** Анализ
- **Планируемая версия:** 2.8.14
- **Срок:** (не указан)

**WUI-3786** — Доработки управлением микрофоном
- **SD заявка:** SD91024
- **Описание:** 
  1. Большая кнопка "микрофон" в режиме рации (PTT) должна включать микрофон ГГС не всем завешенным вызовам, а только выбранному в настоящий момент (и синхронизировать соответствующее состояние микрофона и пиктограмм завешенных вызовов в части работы микрофона). Режим "переключения" - одним нажатием включается микрофон завешенного вызова, а микрофоны остальных вызовов выключаются.

К примеру верхняя первая кнопка управляет крайним левым верхним завешенным, вторая - крайним левым вторым сверху завешенным и т.д. ## 13. Техническое задание

### 13.1. Общий принцип работы

Программная консоль для трейдинга должна иметь возможность обрабатывать в режиме онлайн десятки одновременных вызовов. Данная функциональность принципиально отличается от классической обработки вызовов применением способа «завешивания» звонков.

**Отличие от классической телефонии:**
- **Стандартная ситуация:** Пользователь принимает первый звонок на трубку или переключает его на громкую связь (на спикер) для разговора. При поступлении второго входящего звонка оповещение отображается на дисплее, но пользователь может говорить второму абоненту только когда первый будет поставлен на удержание (на холд).
- **Консоль трейдера:** Пользователь имеет возможность говорить одновременно всем «завешенным линиям» или слушать одновременно все «завешенные» (поставленные на громкую связь) вызовы. Данный функционал критичен для работы трейдера.

### 13.2. Рабочий процесс пользователя

1. **Начало рабочего дня:**
   - Пользователь приходит на свое место и осуществляет вход в консоль
   - На экране вводятся индивидуальные логин и пароль
   - На консоли подгружается преднастроенный интерфейс с необходимыми пользователю:
     - Кнопками быстрого набора
     - Полями, размещенными в нужных частях экрана
     - Функциями и настройками

2. **Завешивание линий:**
   - Пользователь начинает обзванивать контрагентов
   - Нажимает кнопку быстрого набора первого контрагента (например, "Банк МКБ")
   - Дозванивается до своего коллеги (трейдера другого банка)
   - Предлагает ему завесить линию, говоря по трубке
   - Получая положительный ответ, нажимает кнопку свободного спикер канала на поле (аплете) спикер-каналов
   - Звонок завешивается на этом канале
   - Этот звонок висит активным (подвешенным) в течение всего рабочего дня, пока сам пользователь или контрагент не сбросят его принудительно

3. **Работа с завешенными линиями:**
   - Пользователь может завесить до 16 активных вызовов одновременно
   - Все завешенные линии работают параллельно
   - Пользователь слышит всех контрагентов через громкую связь (спикер)
   - При активности контрагента кнопка спикер-канала мигает (VAD)
   - Пользователь может увеличить громкость для прослушивания важной информации
   - Для ответа пользователь нажимает кнопку микрофона на линии и говорит в микрофон

### 13.3. Реализация функций

#### 13.3.1. Кнопка группового вызова

Кнопка может работать в одном из двух режимов:

**Режим 1: Предварительно запрограммированная группа**
- Кнопка предварительно запрограммирована для определенных спикер-каналов (например, первых четырех)
- Нажатием на кнопку активируется микрофон для этих спикер-каналов
- Голосовая информация, которую говорит пользователь в микрофон, слышат контрагенты, завешенные на этих каналах
- Повторным нажатием кнопки группового вызова микрофон сбрасывается со всех спикер-каналов

**Режим 2: Выборочная активация**
- Нажатием активируется функционал группового вызова
- Пользователь дополнительно выбирает нажатием на определенные линии спикер-канала тех контрагентов, которые будут его слышать (например, первый спикер-канал, третий и четвертый)
- При повторном нажатии на кнопку группового вызова вызов сбрасывается

#### 13.3.2. Конференция

- Нажатием кнопки конференции пользователь имеет возможность добавлять к текущему звонку или завешенной линии еще одного участника

### 13.4. Использование внешних устройств

#### 13.4.1. Одновременное использование устройств

- **Микрофон + две трубки** — возможность одновременного использования
- **Микрофон + трубка + гарнитура** — комбинированное использование
- Переключение между устройствами для работы с разными контрагентами

#### 13.4.2. Индикаторы активности

- Активная трубка (или гарнитура) подсвечивается зеленым цветом
- Визуальное отображение статуса всех используемых устройств
- Быстрая идентификация активного устройства

#### 13.4.3. Переключение между устройствами

**Быстрое переключение с одной трубки на другую:**
- Если пользователь говорит по одной трубке с одним контрагентом, а по другой трубке — с другим контрагентом
- Возможность мгновенного переключения для управления разговорами

**Быстрое переключение с трубки на спикер-канал:**
- Контрагент уже завешен на спикер-канале
- Контрагент начинает что-то говорить, кнопка спикер-канала начинает мигать (VAD)
- Пользователь хочет поговорить с ним «приватно», т.е. по трубке
- Пользователь нажимает кнопку мигающего спикер-канала
- Затем нажимает кнопку трубки на поле активности трубок
- Звонок переключается со спикер-канала на трубку для приватного разговора

**Управление микрофоном ГГС через кнопки модуля Goose:**
- Кнопки клавиш линий модуля Goose (8 клавиш) могут использоваться для управления микрофоном ГГС завешенных вызовов
- Маппинг один-в-один: верхняя первая кнопка управляет крайним левым верхним завешенным, вторая - вторым сверху и т.д.
- Для групп завешенных вызовов можно сделать маппинг один-в-один сверху вниз

**Переключение со спикера обратно на спикер-канал:**
- Пользователь говорит по активному звонку на трубке
- Хочет снова завесить звонок на спикер-канал
- Во время активного звонка на трубке нажимает свободную линию на поле спикер-каналов
- Звонок переключается с трубки на спикер-канал и там остается висеть активным

### 13.5. Статус линий, работа в команде

#### 13.5.1. Мониторинг линий коллег

- Возможность мониторить линии коллег
- Отображение статуса линии: «свободна» или «занята»
- При занятости отображение:
  - Телефонный номер
  - Имя из записной книжки
  - Понимание, с кем разговаривает сотрудник

#### 13.5.2. Организация линий

- Линии обычно расположены на вкладках (страницах)
- Названия вкладок можно редактировать
- Переключение между вкладками для доступа к разным группам линий

#### 13.5.3. Совместная работа

- **Подхват входящего звонка коллеги** — возможность принять звонок, который поступил коллеге
- **Перевод звонка** — возможность перевести звонок на другой внутренний или внешний номер
- **Вклинивание в разговор** — возможность вклиниваться в разговор коллег, который был завешен ранее
- **Быстрое вклинивание** — желательно делать это достаточно быстро в одно-два касания, например, однократным нажатием на поле с завешенным звонком на соседней вкладке
- **Переадресация** — возможность устанавливать переадресацию без условия или в случае отсутствия ответа с самого устройства или программного клиента

## 14. Глоссарий

- **RTUM** — RTU Management, backend сервер для управления телефонией
- **SIP** — Session Initiation Protocol, протокол для установки сессий
- **WebRTC** — Web Real-Time Communication, технология для реального времени коммуникаций
- **PWA** — Progressive Web App, прогрессивное веб-приложение
- **FSD** — Feature-Sliced Design, архитектурная методология
- **Goose** — аппаратный модуль, содержащий микрофон типа "гусиная шея" (ГГС) и набор из 8 клавиш для привязки контактов с LED подсветкой
- **Handset** — телефонная трубка
- **Hub** — центральный хаб контроллера
- **Presence** — статус присутствия пользователя
- **DTMF** — Dual-Tone Multi-Frequency, тональный набор
- **BLF** — Busy Lamp Field, индикация занятости линии
- **IVR** — Interactive Voice Response, интерактивное голосовое меню
- **LDAP** — Lightweight Directory Access Protocol
- **AD** — Active Directory
- **VAD** — Voice Activity Detection, обнаружение речевой активности
- **PTT** — Push-to-Talk, режим "рации" (нажми-говори)
- **ГГС** — Гусиная шея, микрофон-подвеска типа "гусиная шея", встроенный в модуль Goose для работы в трейдинг-деске в режиме PTT (Push-to-Talk)
- **Спикер-канал** — канал громкой связи, на который завешиваются звонки
- **Завешенная линия** — активный звонок, поставленный на громкую связь и работающий в фоновом режиме
- **Трейдинг-деск** — рабочее место трейдера в торговом зале
